## 一、本地 ↔ 服务器 代码同步

本地源：`D:\xiangmu\gongkao`　服务器：`/home/ubuntu/gongkao`

**修改流程（重要）：**
1. 在本地 `D:\xiangmu\gongkao` 修改代码
2. 上传到服务器（SFTP，用户 `ubuntu@YOUR_SERVER_IP`）
3. **必须重建镜像**（Cache 模式，几秒钟）：
   ```bash
   cd /home/ubuntu/gongkao
   docker compose build backend frontend    # 缓存模式，只重做 COPY 层
   docker compose up -d backend frontend     # 重建容器
   ```
4. 验证 `curl http://localhost:3000/api/health`（返回 teachers 数组即正常）
5. git 提交（服务器上）：`git add -A && git commit -m "描述"`

> ⚠️ 魔咒：**只 `up -d` 不重建 = 改动不生效**（因为代码在镜像里）。改 `api.py`/`index.html` 必走 `build`。
> ⚠️ 绝对不要 `docker compose build --no-cache`：pip 全量重装会卡 20+ 分钟。

## 五、接口契约速查

### 问答 SSE 事件流（POST /api/ask）
| 事件 | data 字段 | 说明 |
|---|---|---|
| `start` | session_id | 会话建立/沿用 |
| `delta` | text | 增量文本 |
| `refs` | references[] | 引用片段 {doc_name, score} |
| `guard_block` | fails[] | 幻觉拦截（reference/fact/out_of_scope），结束流 |
| `error` | message | 服务异常 |

请求体：`{query, teacher_id, stream?, session_id?, }`，登录用户带 `Authorization: Bearer <token>` 计额度。

### 账号（POST /register、/login，GET /me）
- register/login 响应：`{token, username, role, quota_left}`
- me 响应：`{anonymous:true}` 或 `{anonymous:false, username, role, quota_left}`
- register_oauth 自动建号规则见项目状态总览 §4.6

### Gitee OAuth（/api/auth/gitee/*）
- `GET /api/auth/gitee/status` → `{enabled: bool}`
- `GET /api/auth/gitee/login` → 307 跳授权页（未配置 503）
- `GET /api/auth/gitee/callback?code&state` → 302 回 `/?token=xxx`（state 错 400 / 换取失败 502）

### 知识库
- `POST /api/upload?teacher_id=x`（multipart，X-Upload-Secret；3 次/分限流；50MB 上限）
- `GET /api/documents?teacher_id=x` / `POST /api/documents/delete`
- 上传/删除后缓存自动失效

## 六、管理后台与运营看板（C2/C3）

### 6.1 入口与凭据

| 页面 | 地址 | 凭据 |
|---|---|---|
| 管理后台 | `http://<host>:3000/admin.html`（`/admin` 302 跳转） | admin / admin123（.env 的 ADMIN_USERNAME/ADMIN_PASSWORD） |
| 运营看板 | `http://<host>:3000/dashboard.html` | X-Admin-Secret 头 = `CHANGE_ME_ADMIN_SECRET`，或 admin Bearer token |

### 6.2 后台 4 个 tab

1. **📊 统计**：总用户/会员/在线老师/知识块/文档数
2. **👨🏫 老师管理**：老师列表 + 新增/编辑/上下线（改温度/召回数/阈值即时生效，缓存自动失效）
3. **👥 用户管理**：搜索 + 角色设置（免费/会员/天数）
4. **📚 文档管理**（2026-09-04 补）：按老师筛选文档列表（doc_name/chunks）+ 删除（confirm + 事件委托），复用 `/admin/documents` 接口

### 6.3 新增后台功能须注意

- 后端路由必须挂 `_admin_user(authorization)` 守卫（401 无 token / 403 非 admin）
- 新增环境变量须同步改 `docker-compose.yml` 的 backend.environment（compose 无 env_file，.env 不会自动注入）
- 前端 admin.js 为纯原生 JS，tab 切换走 `switchTab(tab)` + `renderXxx()` 模式

## 七、多老师扩展

新增老师（如 T003）：
1. `backend/poc/config.py::TEACHERS` 加一条（teacher_id/TEACHER_NAME/TEACHER_SUBJECT/llm_model/temperature/top_n/threshold）
2. 在服务器 `.env` 不需要动（注册表是代码）
3. `docker compose build backend && docker compose up -d backend`
4. 前端 `teacherTabs` 自动出现（loadTeachers 读 /api/teachers）
5. 上传课件时选 `teacher_id=T003`

其他老师可用不同 LLM 模型（llm_model 字段覆盖全局默认）。
