## 四、已实现功能清单（含接口）

### 1. 多老师 RAG 问答
- 老师注册表 `backend/poc/config.py::TEACHERS`：新增老师加一条即可（teacher_id/name/subject/llm_model/temperature/top_n/threshold）
- 每师独立 Chroma collection（`teacher_{teacher_id}`），知识库严格隔离
- SSE 流式输出（`POST /api/ask?stream=true`），事件：`start/delta/refs/guard_block/error`

### 2. 会话历史持久化（`backend/poc/chat.py`，SQLite 落卷）
- 接口：`GET /api/sessions?user_id=xxx`、`GET /api/sessions/{id}/messages`、`POST /api/sessions/{id}/delete`
- 侧栏 UI：历史列表 / 新建 / 删除；登录用户会话绑定其 user_id，匿名会话绑定 `anonymous`
- 多轮上下文注入上限 `HISTORY_LIMIT=10` 轮（api.py）

### 3. 双层缓存（`backend/poc/cache.py`）
- 检索缓存 + 回答缓存（TTLCache，进程内）
- 知识库变更（上传/删除文档）自动失效对应缓存
- 热查询直接命中，不重复调 LLM

### 4. 幻觉检测三道关卡（`backend/poc/guard.py`）
| 关卡 | 规则 |
|---|---|
| ① 无资料拒答 | 无检索命中（低于 threshold）→ 拒答 |
| ② 引用一致性 | 答案中每个数字（**含中文数字**"百分之九十九点七"）必须出现在检索片段中 |
| ③ 超纲反查 | 超纲结论句子用 embedding 反查知识库，相似度 < 0.28 拦截；`selftest` 模式跳过（哈希向量无语义） |

- 流式 `guard_block` 事件 + 前端拦截提示；`GET /api/guard/stats` 实时计数
- 拦截原因：`reference`（引用不符）/ `fact`（数字不符）/ `out_of_scope`（超纲）

### 5. 用户账号/会员额度（`backend/poc/auth.py`，SQLite 落卷）
- 接口：`POST /api/register`、`POST /api/login`、`GET /api/me`、`GET /api/auth/gitee/*`
- 密码：PBKDF2-HMAC-SHA256（16B salt，12 万迭代）；token：user_id+时间戳+HMAC 签名，7 天有效
- 额度：free 20 次/天、member 200 次/天（跨天自动重置）；**匿名不限量**（不打断验收）
- 表：`users` + `oauth_links`（provider/provider_uid 联合主键绑定）

### 6. Gitee OAuth 第三方登录（`backend/poc/gitee.py`）
- 流程：前端 🦊 按钮 → `/api/auth/gitee/login`（307 跳 Gitee 授权页，state 防 CSRF）→ 回调 `/api/auth/gitee/callback` → code 换 token → 拉用户 → 自动建号/绑定 → 302 回首页 `/?token=xxx` → 前端存 localStorage
- 自动建号：用户名 `Gitee昵称@gitee`（重名自动加序号）、随机密码（只能 Gitee 登录）
- 未配置 `GITEE_CLIENT_ID/SECRET` 时优雅降级（status→enabled:false、login→503、按钮提示"暂未开放"）
- **配置指引**：见 `Gitee登录配置指引.md`（凭据已部署，线上已启用）
- ⚠️ 路由前缀：nginx `/api/` 规则会剥掉 `/api` 前缀，后端路由实为 `/auth/gitee/*`（对外 URL 带 `/api`）

### 7. 前端登录/注册/登出 UI（`frontend/index.html`）
- 右上角账号区（未登录：登录/免费注册按钮；已登录：用户名+剩余额度+退出）
- 登录/注册模态框（模式切换/回车提交/遮罩关闭/注册后自动登录）
- token 存 localStorage，`send()` 自动带 `Authorization: Bearer` 头计额度
- 启动时解析 URL `?token=`（OAuth 回调）并清除地址栏

### 8. 监控指标（`backend/poc/metrics.py`，零依赖）
- `GET /api/metrics`：uptime / 请求计数（method+path）/ 状态码分布 / ask 统计（total/fail/avg_latency_ms）/ 老师分布 / 最近事件
- `GET /api/metrics/prometheus`：Prometheus 文本格式（`gk_*` 指标）
- 全链路请求中间件自动记录（方法/路径/状态码/耗时）

### 9. 知识库管理
- `POST /api/upload?teacher_id=xxx`（X-Upload-Secret 鉴权，nginx 3 次/分钟限流，50MB 上限）
- `GET /api/documents?teacher_id=xxx`、`POST /api/documents/delete`（删文档自动失效缓存）
- 支持 md/txt/docx/pptx/pdf；分块 600/120

## 五、关键设计决策与坑（重要！）

1. **Docker 镜像重建**：`api.py`/`index.html` 是 COPY 进镜像的，**改代码后必须 `docker compose build`（缓存模式）再 `up -d`**，只 `up -d` 不生效
2. **`docker compose build --no-cache` 会卡死**：pip 全量重装（曾 20+ 分钟），必须用缓存模式
3. **HF 拉模型**：必须 `HF_HUB_DISABLE_XET=1` + `HF_ENDPOINT=https://hf-mirror.com`（直连官方 401）
4. **nginx ask 超时**：须 300s（LLM 实测最慢 121s），120s 会误杀
5. **数据持久化**：auth.db/chat.db 必须落 `/data` 挂载卷（曾踩坑：默认相对路径落在容器可写层，重建即丢；已修：compose 钉死 `AUTH_DB=/data/auth.db`、`CHAT_DB=/data/chat.db`）
6. **LLM 模型**：中转站 21 个模型中仅 `gpt-5.6-luna` 稳定可用（deepseek-chat 等 503）
7. **Embedding**：中转站无 embedding 通道 → 本地 fastembed bge-small-zh
