## 一、需求拆分（R1~R4）

### R1 题目自动分类
- R1.1 AI 采集入库的每道题自动打**课程分类**标签（8 大类枚举，与老师管理一致）。
- R1.2 题库管理页每题可见分类、可按分类筛选、可编辑；手动录入也必须可选分类。
- R1.3 存量无分类题目支持**一键 AI 补充分类**（批量）。
- R1.4 分类统计（分布卡片）。

### R2 整套试卷采集完整性 + 图形推理
- R2.1 整套试卷（5~15 万字）上传采集，**不得静默丢弃**任何部分；超容量必须显式告警。
- R2.2 分批不得拦腰截断题目（按题号边界切批）。
- R2.3 提取结果与原文题数**全局对账**，缺口明显时返回告警（而非静默少收）。
- R2.4 **图形推理题**（题干/选项均为图片标记、文字极少）必须被采集，图片标记保留在题干与选项中。
- R2.5 管理端详情与学生端练习页的**选项图片**必须渲染（现状选项为纯文本，图片标记显示为字符串）。

### R3 答案 AI 解析
- R3.1 管理端可对单题生成**多角度 AI 解析**（审题/思路/逐项分析/易错警示/考点归纳），覆盖原解析需确认。
- R3.2 支持**批量生成**（针对无解析题目，限量防超时）。
- R3.3 解析落库到 question_bank.analysis，全端（详情/练习反馈）即时生效。

### R4 知识体系上传 API 排查与增强
- R4.1 实测线上接口，确认"未实现"反馈的真实原因。
- R4.2 兼容最常见的调用误用形态（teacher_id 放 query），返回信息防呆（404 附可用老师列表）。
- R4.3 新增持钥可查的可用老师列表端点，外部 AI 可自查 teacher_id。
- R4.4 输出防呆版调用文档（curl + Python 双示例 + 错误对照表）。

## 二、现状分析（摸底结论）

### 2.1 分类现状（R1 根因）
系统存在**三套互不打通的分类维度**，这是"分类管理没生成"感受的根源：
| 维度 | 存储 | 现状 |
|---|---|---|
| 题型树关联 | `question_bank.category_id → knowledge_nodes(node_id, tree_type=qtype)` | 列表筛选/表单下拉已用，但 AI 采集**不输出**该字段 → 采集题全部为空 |
| 分类管理页 | 独立表 `question_category`（CRUD/排序/启停 UI 完整） | **与题目零关联**——用户建了分类，题库选不到 |
| 知识点 | `question_bank.knowledge_point` | AI 采集自动填，是细分标签不是大类 |

**结论**：缺一个 AI 采集自动打标、每题必有、全端可筛选的**大类字段**。

### 2.2 采集链路现状（R2 根因，双层截断）
```
前端 extractQuestions(): _splitQbBatches(text, 8000, 12)   ← 最多 9.6 万字，超出 confirm 后静默丢
  └→ POST /admin/questions/extract {text: 每批 8000 字}
       └→ admin.extract_questions_ai(): _split_batches(text, 2500, 12)  ← 单请求最多 3 万字，超出静默丢
            └→ 逐批 LLM 提取（串行）+ 批内 0.75 漏题回采
```
- 整套行测卷（130 题，6~10 万字）**必然**触发前端上限丢弃 → "题目数量不全"。
- 切批按 `\n` 段落边界（找不到则硬切）→ 题目可被拦腰截断。
- prompt 无图形推理专则 → 纯图片标记题被 LLM 跳过 → "图形推理无法采集"。
- 选项渲染（管理端详情 2015 行 / 学生端 c4-study.js 274 行）为纯文本 → 即使采集到图片标记也显示不出来。

### 2.3 解析现状（R3）
`question_bank.analysis` 已有；采集时 LLM 可带出原文解析（无则空）。无 AI 生成/补写能力。

### 2.4 知识 API 现状（R4 实测，2026-09-06 探测）
| 用例 | 结果 |
|---|---|
| GET /api/v1/knowledge/health | ✅ `enabled:true` |
| 正常上传（T003） | ✅ 200，2 节点创建成功 |
| teacher_id 不存在 | ✅ 404 + 明确 message |
| 无 X-API-Key / api_key 放 form | ✅ 401 |
| 无 /api 前缀（裸 /v1/...） | ⚠️ nginx 405（HTML 错误页，无指引） |
| teacher_id 放 query | ⚠️ 400 "缺少 teacher_id"（不吸收 query 值） |

**结论：服务端功能已实现且在线**。"未实现"的感知极可能来自外部 AI 的调用姿势踩坑（URL 前缀错/参数位置错/teacher_id 错），且错误响应未提供自助纠错信息。

## 四、实现方案

### 4.1 R1 自动分类
1. **采集侧**：extract prompt 增加字段规则——`category: 从 [言语理解/判断推理/数量关系/资料分析/常识判断/申论/面试/综合] 中选 1 个`；`_normalize_questions` 归一化（别名映射→枚举校验→非法兜底"综合"）。
2. **入库侧**：`add_question/add_questions_batch/update_question` 透传并校验 category。
3. **补标侧**（ai-categorize）：一次 LLM 调用批量判定——请求带 `[{id, qtype, 题干前120字}]`（≤50 题），要求输出 `[{"id":n,"category":"…"}]`；逐条校验枚举后 UPDATE。JSON 解析失败/字段缺失 → failed 计数，不中断。
4. **前端**：QB_CATEGORIES 常量与后端枚举一字面对齐；筛选/列表/表单/采集确认页/统计卡全覆盖。

### 4.2 R2 采集完整性
1. **后端切批重写**：`_split_batches` 优先**题号行边界**（`(?m)^\s*\d{1,3}[.．、)）]\s`）→ 次选段落边界 → 兜底硬切；`MAX_BATCHES 12→60`（单请求容量 3 万→15 万字）。
2. **批间并发**：`ThreadPoolExecutor(max_workers=3)` 并发跑 `extract_piece`（纯网络 IO；llm 网关 429 风险≈3×8s≈22 次/min，远低于 RPM 限制）；结果**按批序**回主线程 absorb 去重（线程安全：seen_keys 仅主线程写）。
3. **全局对账**：`n_expected = _count_question_floor(全文)`；`len(all_questions) < n_expected*0.9` → warning；被丢弃的尾部字数 → warning（不再静默）。
4. **图形推理专则**（prompt）：
   > 图形推理题规则：题目可能几乎无文字、主要由图片标记构成（题干图 + 四个选项图）。此类题**必须输出**：question = 题干文字 + 题干图片标记；options 每项 = 选项字母 + 对应图片标记（如 "A. ![图2](/api/qimg/...)"）。禁止因文字少而跳过。
5. **前端容量**：`IMP_BATCH_CHARS 8000→100000`、`IMP_BATCH_MAX 12→4`（单次总容量 40 万字，整套试卷单请求）；confirm 超限文案同步；进度条保留；渲染 warnings。
6. **选项图渲染**：管理端详情 `options.map(qText)`；学生端 `renderQText(opt)`。

### 4.3 R3 AI 解析
1. prompt 结构（按题型微调）：
   ```
   【审题】关键信息与限定条件拆解
   【思路】解题路径（方法/公式/切入点）
   【选项分析】逐项排除/锁定依据（choice）｜【判定依据】（judge）｜【评分要点】（essay）
   【易错警示】常见误区与陷阱
   【考点归纳】知识点 + 同类题延伸
   ```
2. 单题端点：读题 → LLM（走 effective_default 通道）→ 覆盖 analysis 落库 → 返回新解析。
3. 批量端点：取 analysis='' 的题（limit≤20，并发 3），逐题生成落库；失败计入 failed 不中断。
4. 前端：详情弹窗「✨ AI 解析」（有原解析时 confirm 覆盖）；批量栏「✨ 批量 AI 解析」。

### 4.4 R4 知识 API 防呆
1. upload：`teacher_id` Form 为空时回读 query 参数（吸收最常见误用）。
2. 404 响应 data 附 `{available_teachers: [{teacher_id, name}≤20]}`。
3. 新增 `GET /v1/knowledge/teachers`（同限流/鉴权），返回启用老师列表。
4. 成功响应 data 附 `hint`（去管理后台哪里看）。

## 五、风险评估与对策
| 风险 | 对策 |
|---|---|
| 并发提取触发 LLM 网关限流（429） | 并发=3（实测 RPM 余量充足）；单批已有 3 次重试 |
| 15 万字单请求耗时逼近 nginx 600s | 60 批/3 并发 ≈ 20 轮×8s ≈ 160s + 回采余量；前端 timeout=600s 保留 |
| LLM 分类误判 | 枚举校验兜底"综合"；可手动编辑修正；AI 补充分类可重跑 |
| 存量数据 category 全空 | 不迁移默认值（空=未分类，可筛选可补标）；「AI 补充分类」按钮一键补 |
| category 列迁移 | 幂等 ALTER（OperationalError 吞掉），旧库平滑升级 |
| 知识 API query 兼容引入歧义 | 仅 Form 缺失时读 query；Form 优先级不变 |
| 回归破坏 | 全部变更为增量（新列/新端点/新参数），regression.py 65 用例回归把关 |
