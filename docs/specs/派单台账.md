## 一、用法（给统筹自己看）

1. 派单前：确认该模块「依赖前置」已全部验收通过，否则不算可开工。
2. 派单时：把「派给」填成 `AI-1 / AI-2 / ...`，把「交付状态」改为 `已派`；话术从 `docs/specs/modules/` 对应说明书 + 本文「已拟话术」章节取。
3. 收到交付后：按每条模块说明书的「完成标准」逐项验，通过才把「验收状态」改为 `通过`；不通过改为 `返工` 并写明原因。
4. 交叉验收兜底：任何改动若跨模块，需同时跑 `docs/测试清单.md` 回归 + `docker compose build`（缓存模式）重启。
