## 1. 项目定位与目标

**产品**：多老师专属垂直大模型平台 —— 面向公考「言语理解/逻辑判断」教学的 RAG 问答平台。

**核心价值**：多位老师各挂载私有课件知识库，回答**严格基于已入库资料**，「零训练、零微调」，纯检索增强（RAG）+ LLM 推理，用「幻觉检测三道关卡」保证回答不编造、不超纲。

**可运营目标**（本次设计新增，对应 C 系列扩展域）：

1. 具备完整**会员付费闭环**（免费试用 → 付费升级 → 额度消耗 → 续费）
2. 具备**内容与老师管理后台**（课件入库/删除、老师配置 CRUD、会员管理）
3. 具备**运营数据看板**（请求量、转化、额度消耗、幻觉拦截、老师热度）
4. 具备**学员增值功能**（学习记录、错题/收藏、真题练习等）

***

## 2. 双端定义

| 端   | 名称         | 职责边界                               | 技术形态                            |
| --- | ---------- | ---------------------------------- | ------------------------------- |
| 网站一 | 前端业务站点     | 面向学员的交互入口：登录/选老师/会话提问/结果渲染         | 纯静态 `frontend/`，nginx :3000 对外  |
| 网站二 | RAG 内核服务站点 | 面向系统/前端的 API 服务：鉴权/知识库/检索/调度/推理/校验 | FastAPI `backend/poc/`，:9000 内网 |

**通信模型**：

```text
学员浏览器 ──HTTPS(规划)──▶ frontend (nginx :3000)
                              │  /api/ 前缀剥离
                              ▼
                     backend (FastAPI :9000 内网)
                              │
        ┌─────────────────────┼─────────────────────┐
        │ 知识库(Chroma)  会话(SQLite)   账号(SQLite) │
        │ 向量检索+幻觉守卫  chat.db       auth.db    │
        └─────────────────────┴─────────────────────┘
                              data/ 挂载卷（重建容器不丢）
```

## 3. 技术栈（已定型，模块须遵循）

| 层         | 选型                                    | 说明                                           |
| --------- | ------------------------------------- | -------------------------------------------- |
| 前端        | 原生 HTML/CSS/JS（纯静态，无构建）               | `frontend/index.html` 单文件                    |
| 反向代理      | nginx                                 | `/api/` 反代、SSE 300s、上传限流                     |
| 后端        | Python 3.12 + FastAPI                 | `backend/poc/` 包                             |
| 向量库       | Chroma（PersistentClient）              | 每师一 collection：`teacher_{teacher_id}`，cosine |
| Embedding | 本地 fastembed `BAAI/bge-small-zh-v1.5` | `EMBED_PROVIDER=local`（中转站无 embedding 通道）    |
| LLM       | 中转站 `gpt-5.6-luna`（OpenAI 兼容）         | `API_BASE_URL=https://ai.anyyds.cn/v1`       |
| 关系存储      | SQLite（标准库，零依赖）                       | `auth.db` / `chat.db`，WAL 模式，落 `/data` 卷     |
| 缓存        | 进程内 TTLCache                          | 检索 5min + 回答 10min                           |
| 账号        | 本站账密 + Gitee OAuth                    | PBKDF2-HMAC-SHA256、HMAC-signed token（7 天）    |
| 监控        | 自研零依赖 metrics                         | `/api/metrics` JSON + Prometheus 文本          |
| 编排        | Docker Compose                        | `gongkao-backend` / `gongkao-frontend`       |

## 5. 关键全局约束（所有模块必须遵守）

1. **多老师隔离**：任何存储、检索、缓存操作必须带 `teacher_id`；collection 命名 `teacher_{teacher_id}`；缓存键含 teacher 前缀。
2. **稳定函数契约**：`store.py` 的 8 个函数签名、`answer.py::ask` 返回结构、`api.py` 的路由与响应字段是对外/跨模块契约，**模块重构不得变更签名**。
3. **缓存与守卫顺序**：LLM 答案**必须先跑** **`run_guard`** **再写缓存**；幻觉拦截的结果绝不入缓存（否则脏答案被复用）。
4. **数据持久化**：`auth.db`/`chat.db` 必须落 `/data` 卷（compose 已钉死 `AUTH_DB`/`CHAT_DB`），禁止使用容器内部相对路径默认值。
5. **Docker 重建纪律**：改 `api.py`/`index.html` 后必须 `docker compose build`（**缓存模式**）再 `up -d`；**禁用** **`--no-cache`**（pip 全量重装会卡死）。
6. **模型拉取**：本地 embedding 首次拉模型必须 `HF_HUB_DISABLE_XET=1` + `HF_ENDPOINT=https://hf-mirror.com`。
7. **LLM 可用性**：中转站 21 模型仅 `gpt-5.6-luna` 稳定；deepseek 等 503。B7 需含重试降级（C 系列补齐）。
8. **路由前缀**：nginx `/api/` 尾斜杠会剥掉 `/api` 前缀，后端路由实为 `/ask`、`/auth/gitee/*`（对外 URL 带 `/api`）。
9. **匿名策略**：当前匿名不限额度（不打断验收）；登录用户才计额度（free 20 / member 200 每日）。C1 可能收紧此策略，须保持向后兼容。
