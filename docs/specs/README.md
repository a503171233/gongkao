## 1. 这套东西是什么

把「多老师专属垂直大模型平台」从「能跑的原型」升级为「可运营的双端项目」，并拆成 **18 个边界清晰、可独立开发、可独立验收** 的模块。每个模块都有独立开发说明书，可以交给不同的 AI 并行实现，再统一由统筹汇入验收。

## 3. 分派模板（给其他 AI 的 prompt 骨架）

> 你是模块 `<编号>` 的实现者。请先读 `docs/specs/00-总设计.md`、`02-数据契约.md` 和 `modules/<编号>-<名字>.md`，只改模块说明书里指定的文件，遵循 `docs/项目状态总览.md` §五/§六 的坑位纪律。完成后附自测结果。

## 4. Handoff 检查点（每模块验收必查）

- [ ] 模块说明书里的「验收标准」全部通过
- [ ] 未改动模块说明书「允许修改文件」以外的文件
- [ ] 未引入新的第三方依赖（如有，已向统筹申请）
- [ ] 契约字段与 `02-数据契约.md` 完全一致（无字段漂移）
- [ ] 自测命令可复现（单元测试 / CLI / curl 任选）
- [ ] 缓存与守卫顺序正确（先守卫后缓存）、多老师隔离保持

## 5. 统筹流程

1. **分派**：按 `01-模块分解.md §5` 批次派单，先内核对后端、先契约后前端。
2. **开发**：各 AI 按模块说明书独立实现。
3. **验收**：统筹按 §4 检查点逐项核验。
4. **汇入**：改动汇入主分支，跑 `docs/测试清单.md` 全量回归 + 线上冒烟。
5. **沉淀**：更新 `docs/项目状态总览.md`（里程碑/遗留），把新决策写回 `docs/排障笔记.md`。

## 6. 纪律红线（重复强调）

- 改 `api.py`/`index.html` 后必须 `docker compose build`（**缓存模式**）再 `up -d`；**禁用 `--no-cache`**。
- `auth.db`/`chat.db` 必须落 `/data` 卷，禁止用容器相对路径默认值。
- 本地 embedding 拉模型需 `HF_HUB_DISABLE_XET=1` + `HF_ENDPOINT=https://hf-mirror.com`。
- 中转站仅 `gpt-5.6-luna` 稳定可用。
- nginx `/api/` 前缀剥离，后端路由不含 `/api`。
