# B4 · 调度控制模块（网站二 内核）

## 1. 目标

问答主链编排：检索 → 阈值过滤 → 拒答分支 → Prompt 组装 → LLM 调用 → 幻觉校验 → 回答缓存，统一返回 dict 或流式事件生成器。是 `answer.ask()` 的核心。

## 2. 现状

`backend/poc/answer.py`：`ask()`、`_retrieve_hits()`、`_threshold()`、`_gen_reject()`、`_gen_mock()`、`_stream_chain()`。

## 3. 稳定契约（`02` §6.2）

```
ask(query, teacher_id="T001", stream=False, history=None)
  非流式 → dict{answer, hits, rejected[, mock, guard_fails]}
  流式   → 生成器 yield {type: delta|refs|done|guard_block, data}
```

## 4. 主链时序（必须保持）

```
strip(query)，空则 ValueError
_retrieve_hits：store.retrieve 后按 threshold 过滤
  无命中 → 拒答（不调 LLM）｜selftest → 返回 Top1 模拟
  无 API_KEY → RuntimeError
build_messages（B6）
非流式：查 answer_cache → 未命中 _call_llm → run_guard → 拦截则拒答(不入缓存) → 写缓存
流式：  _stream_chain 边推边累积 → done 前 run_guard → 拦截发 guard_block 终止
```

## 5. 功能点清单

1. 阈值：`selftest` 用 0.1（哈希向量语义弱），真实用老师 `threshold`（默认 0.5）。
2. 拒答分支：无命中直接返回 `REJECT_TEXT`，`rejected=true`，不消耗 LLM。
3. 缓存：键 `ans|{teacher_id}|{query}|{hist_hash}`（含历史哈希防多轮串味）；仅缓存非流式、非拒答、非 mock。
4. 守卫顺序：**先 `run_guard` 再写缓存**；拦截结果绝不入缓存。
5. 流式守卫：累积完整回答在 `done` 前校验，拦截则发 `guard_block` 并终止（不发 refs/done）。

## 6. 允许修改文件

- `backend/poc/answer.py`（`ask`/`_retrieve_hits`/`_threshold`/`_stream_chain` 编排部分）

## 7. 验收标准

- [ ] 无匹配 → 拒答且不调 LLM；有匹配 → 正常回答
- [ ] 非流式命中缓存后不重复调 LLM；流式从不走缓存
- [ ] 幻觉拦截结果不进入缓存（再次同样提问仍重新推理）
- [ ] 流式事件顺序/结束符合 `02` §4

## 8. 坑与注意事项

- 历史哈希必须覆盖到缓存键，否则多轮上下文会串。
- B4 只编排，具体检索（B3）/模板（B5）/组装（B6）/调用（B7）/守卫（B8）各自独立，B4 不得内联其具体实现。
