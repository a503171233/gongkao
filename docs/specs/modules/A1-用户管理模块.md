# A1 · 用户管理模块（网站一 前端）

## 1. 目标

实现学员侧的**账号身份管理**：本站密码注册/登录、Gitee 第三方登录、token 持久化、当前用户信息与剩余额度展示、登出。未登录时允许匿名体验（匿名不限额度）。

## 2. 现状

`frontend/index.html` 右上角账号区：未登录显示「登录 / 免费注册」按钮；已登录显示「用户名 + 剩余额度 + 退出」；登录/注册模态框；token 存 localStorage；启动时解析 URL `?token=`。

## 3. 接口依赖（见 `02-数据契约.md` §3.2/§3.3）

| 接口 | 用途 |
|---|---|
| `POST /api/register` | 注册，返回 `{token,user_id,username,role}` |
| `POST /api/login` | 登录，返回 `{token,...,quota_left}` |
| `GET /api/me` | 用 Bearer 头校验 token，返回额度/角色 |
| `GET /api/auth/gitee/status` | 判断 Gitee 是否启用（隐藏/显示按钮） |
| `GET /api/auth/gitee/login` | 跳转授权页（浏览器整页导航） |
| `?token=xxx` | OAuth 回调带回 token |

## 4. 功能点清单

1. 注册模态框：用户名 + 密码（≥6 位）校验、回车提交、遮罩关闭、失败提示。
2. 登录模态框：同上；成功后存 token、刷新账号区、触发额度更新。
3. Gitee 登录按钮：`status.enabled=false` 时显示「暂未开放」或隐藏；点击跳 `gitee/login`。
4. OAuth 回调：从 URL 取 `?token=` → 存 localStorage → 清除地址栏（history.replaceState）→ 刷新账号区。
5. 额度展示：登录后展示 `quota_left`；额度为 0 时给出升级提示文案。
6. 登出：清 token、清 localStorage、恢复未登录态、清空会话区（联动 A3）。

## 5. 模块内契约（前端共享约定）

- **文件归属**：本模块实现 `frontend/js/a1-auth.js`。
- **共享总线**：写入 `GK.store.token`；`token` 变化后广播 `GK.bus.dispatchEvent(new CustomEvent('auth:changed', {detail:{token}}))`。
- **供 A4 使用**：`GK.store.token` 是 A4 加 `Authorization: Bearer` 的唯一来源。
- **localStorage key**：与现有实现一致，建议 `gk_token`（如迁移需兼容旧 key）。

## 6. 允许修改文件

- `frontend/js/a1-auth.js`（新建）
- `frontend/index.html` 中「账号区 / 登录注册模态框」的容器结构（不动其它区块）

## 7. 验收标准

- [ ] 注册→自动登录→账号区显示用户名与 `quota_left`
- [ ] 登录失败（错密码）有明确错误提示
- [ ] Gitee `status.enabled=false` 时按钮隐藏或显示「暂未开放」
- [ ] OAuth 回调后 token 已存且地址栏 `?token=` 被清除
- [ ] 登出后 `GK.store.token` 清空、A3 会话区清空
- [ ] 匿名（无 token）时不报错，账号区显示登录/注册

## 8. 坑与注意事项

- 匿名不限额是既有策略，A1 不得擅自要求匿名登录。
- `Authorization` 头须在 A4 统一加，A1 只负责存 token，不直接发带 token 的业务请求。
- Gitee 登录是**整页跳转**（307/302），不是 fetch；回调地址带 `/api`，注意 nginx 前缀剥离。
