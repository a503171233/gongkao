# A3 · 会话交互模块（网站一 前端）

## 1. 目标

管理学员与当前老师的多轮会话：会话列表展示、新建、删除、历史消息加载、问题输入与发送、把用户发言交给 A4 发起 ask。

## 2. 现状

`frontend/index.html` 侧栏（历史列表/新建/删除）+ 输入框；登录用户会话绑定其 `user_id`，匿名绑定 `anonymous`。

## 3. 接口依赖（`02-数据契约.md` §3.4）

| 接口 | 用途 |
|---|---|
| `GET /api/sessions?user_id=` | 会话列表（按 `last_active_at` 倒序） |
| `GET /api/sessions/{id}/messages` | 历史消息 |
| `DELETE /api/sessions/{id}` | 删除会话 |
| `POST /api/ask`（转发给 A4） | 发起问答；未传 `session_id` 时后端自动新建 |

## 4. 功能点清单

1. 会话列表：登录用户用其 `user_id`，匿名用 `anonymous`；条目展示 teacher + 消息数。
2. 新建会话：清空当前 `session_id`，下次 ask 由后端创建。
3. 历史加载：点击会话 → 拉 messages → A5 渲染历史。
4. 删除会话：调 DELETE → 刷新列表；删除当前会话时清空渲染区。
5. 发送：组装 `{query, teacher_id, stream:true, session_id}` 交给 A4；输入为空不发送。
6. 维护 `GK.store.sessionId`：发送成功（收到 `start` 事件里的 `session_id` 或非流式返回）后回填。

## 5. 模块内契约

- **文件**：`frontend/js/a3-session.js`。
- **共享状态**：`GK.store.sessionId`；`GK.store.userId`（A1 在 `auth:changed` 时写入，A3 据此决定 user_id）。
- **依赖**：A4 负责传输，A3 只编排逻辑；收到 `teacher:changed` 时自动新建会话。A5 负责渲染，A3 只把历史消息数组传给 A5。

## 6. 允许修改文件

- `frontend/js/a3-session.js`（新建）
- `frontend/index.html` 会话侧栏 + 输入区容器

## 7. 验收标准

- [ ] 登录用户会话绑定 user_id，匿名绑定 anonymous，互不可见
- [ ] 新建/删除/切换会话正常，删除当前会话后渲染区清空
- [ ] 连问多轮时 `session_id` 持续传递，历史正确注入（后端 `HISTORY_LIMIT=10` 轮）
- [ ] 空输入不发送；发送后输入框清空

## 8. 坑与注意事项

- 会话归属老师不符（切老师）时后端会重建会话；A3 切老师应主动新建会话，避免用到旧 session_id。
- 多轮上下文由后端控制轮数上限，前端不要私自透传超过 10 轮的自定义历史字段。

### 9.2 模块内契约实现

1. **会话列表**：`GET /api/sessions?user_id=`（走 `GK.api`），`user_id` = `GK.store.userId || 'anonymous'`（A1 在 `auth:changed` 写入 `GK.store.userId`）
2. **新建会话**：清空 `GK.store.sessionId` → 广播 `render:clear` → 下次 ask 后端自动建
3. **历史加载**：`GET /sessions/{id}/messages` → 广播 `history:loaded {messages}` 交 A5/渲染层（A3 不拼 DOM）
4. **删除会话**：`DELETE /sessions/{id}` → 刷新列表；删当前会话 → 清 `sessionId` + `render:clear`
5. **发送**：组装 `{query, teacher_id, stream:true, session_id}` 交 `GK.sse`；空输入不发送；发送后清空输入框
6. **sessionId 回填**：SSE `start` 事件回填 `GK.store.sessionId`（done/refs 亦带）
7. **联动**：监听 `teacher:changed` → 主动新建（防旧 session_id 串老师）；监听 `auth:changed` → 同步 userId + 清 session + 刷新列表

### 9.5 上报事项（与 02-数据契约 不一致处）

1. **`/me` 不返回 `user_id`**（仅 `anonymous`/`username`/`role`/`quota_left`）：A1 `loadAuthUser` 恢复登录态时无法从 `/me` 拿到 `user_id` 回填 `GK.store.userId`（其代码在 212 行用 `d.user_id` 是 undefined，静默跳过）。影响：**刷新页面后 A3 会话列表会退回 anonymous 视图**（登录用户看不到自己的历史会话），直到下次登录/注册（login/register 返回 user_id）才恢复。建议：`/me` 增加 `user_id` 字段（后端小改，跨 B1/A1 契约，A3 不擅自动）。
2. **A1 logout 联动调用的是全局 `newSession/loadSessions`**：已在 index.html 提供薄封装转发到 `GK.newSession/GK.loadSessions`，正常工作。A5 交付迁移渲染时可清理。
3. **A5 尚未交付**：`history:loaded`/`ask:*` 事件当前由 index.html 过渡层（clearChat/renderHistory/流式气泡）接住，A5 交付后需把桥接改指向 `A5.*`（A3 事件协议不变，无需改动 A3）。
