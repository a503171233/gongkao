# C3 · 运营数据看板（扩展业务域）

## 1. 目标

把内核已有指标（`/metrics`）与业务数据（用户/订单/额度/拦截）汇总，做成运营可视看板：请求量、转化、额度消耗、幻觉拦截、老师热度、异常趋势。

## 2. 现状

- `/api/metrics` JSON 已有：uptime/requests/status/by_teacher/ask/avg_latency_ms/recent + guard。
- `/api/metrics/prometheus` 已有 Prometheus 文本。
- **缺失**：业务维度（注册数、会员转化、额度消耗、留存）与看板前端。

## 3. 变更提案（需确认后写入 `02`）

### 3.1 业务聚合接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/stats/overview` | 总用户/会员数/今日新增/今日 ask/今日拦截 |
| GET | `/api/admin/stats/quota` | 额度消耗分布（按日/用户） |
| GET | `/api/admin/stats/revenue` | 订单金额/成交（依赖 C1） |
| GET | `/api/admin/stats/teachers` | 老师维度请求/拦截/满意度 |

`metrics.snapshot` 复用，本模块只做**聚合 + 派生指标**，不重复造轮子。

## 4. 功能点清单

1. 汇总接口：从 `auth.db`（用户/角色/额度）、`chat.db`（会话/消息）、`metrics`（请求/耗时）、`guard_counter`（拦截）、`orders`（C1，可选）聚合。
2. 看板页：概览卡片 + 折线（ask 趋势）+ 柱状（老师热度）+ 表格（拦截原因/最近事件）。
3. 数据驱动：复用 A 系列 `GK.api`（若为独立后台页则复用类似封装），前端图表建议用轻量库或纯 SVG/CSS（**不擅加重依赖，需申请**）。
4. 导出：可选 CSV 导出核心指标（`/api/admin/stats/export`）。

## 5. 允许修改文件

- 新建 `backend/poc/stats.py`
- `backend/poc/api.py` 新增 `/admin/stats/*` 路由
- 前台看板页（复用 `admin.html` 或独立 `dashboard.html`）

## 6. 验收标准

- [ ] overview 数字与实际库一致（用户数/今日 ask/拦截数）
- [ ] 老师维度热度与 `by_teacher` 一致
- [ ] 看板可加载、无白屏，数据与 `/metrics` 吻合
- [ ] 收入页面在 C1 未上线时优雅降级（显示 0 或隐藏）

## 7. 坑与注意事项

- `metrics` 是进程内内存指标，重启即清零；若需长期趋势需落库（本模块可选做「指标快照落库」）。
- 权限：`/admin/stats/*` 需 admin Bearer，匿名不可见运营数据。
- 前端图表库若引入，须先向统筹申请，避免与 `index.html` 体积冲突。

### 8.3 权限方案（双通道，任务书硬性契约 + C2 现状无缝衔接）

任务书写「现状无 admin 角色 → 用 ADMIN_SECRET」。但交付时 **C2 已并发上线 admin 角色**（`_admin_user`/`ensure_admin` 已存在），故采用**双通道**（任一通过即可）：
1. **通道①**：`X-Admin-Secret` 头 == `ADMIN_SECRET` 环境变量（任务书要求，最简自洽，`hmac.compare_digest` 常量时间比较）
2. **通道②**：`Authorization: Bearer <admin token>`（C2 已上线，复用 `_admin_user`，零重复造轮子）

匿名 → 401；普通用户 Bearer → 403；任一通道正确 → 200。C2 后续若收紧/统一鉴权，C3 接口语义不变。

### 8.4 数据聚合（复用现有方法，不重复造轮子）
