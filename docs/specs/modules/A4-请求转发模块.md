# A4 · 请求转发模块（网站一 前端）

## 1. 目标

封装所有对网站二（RAG 内核）的 HTTP/SSE 请求：统一 Base URL 与 Bearer 头、错误处理、SSE 流解析与重连。这是前端唯一允许直接 `fetch`/`EventSource` 代码的模块。

## 2. 现状

`frontend/index.html` 内 `send()` 函数：fetch 非流式 / SSE 流式，自动带 `Authorization: Bearer`，解析 `start/delta/refs/guard_block/done/error`。

## 3. 对外提供能力（供 A1/A2/A3/A5 调用）

| 方法 | 签名 | 说明 |
|---|---|---|
| `GK.api(path, {method, body})` | `(path, opts?) => Promise<json>` | 统一 `/api` 前缀 + Bearer，JSON 请求/响应 |
| `GK.sse(path, body, handlers)` | `(path, body, handlers) => AbortController` | 发起 `POST /ask` 流式，按事件回调节点分发 |

`handlers` 约定：`{ start, delta, refs, done, guard_block, error }`，每个是接收事件 data 的函数。

## 4. 功能点清单

1. Base URL：统一拼 `/api`（对外路径）；本地调试可读 `GK.env.apiBase` 覆盖。
2. Bearer：从 `GK.store.token` 读取，存在则加 `Authorization: Bearer <token>`。
3. 非流式错误：非 2xx 时解析 `detail` 抛给调用方展示（401/403/429/5xx）。
4. SSE 解析：用 `fetch` + `ReadableStream` + TextDecoder 按 `event:`/`data:` 分段（`text/event-stream` 协议见 `02` §4）；不依赖 `EventSource`（因为需要 POST body）。
5. 重连/取消：返回 `AbortController`，切换老师/会话时可取消旧流。
6. 超时兜底：非流式设置合理超时（如 60s），流式靠后端 300s 保证。

## 5. 模块内契约

- **文件**：`frontend/js/a4-request.js`（新建，作为前端传输层）。
- **共享状态读取**：`GK.store.token`、`GK.store.teacherId`、`GK.store.sessionId`。
- **禁止事项**：A1/A2/A3/A5 不得各自 fetch；一律调 `GK.api`/`GK.sse`。

## 6. 允许修改文件

- `frontend/js/a4-request.js`（新建）
- 不直接改 index.html 业务区块（仅如需挂载脚本在 shell 中加 `<script>`）

## 7. 验收标准

- [ ] `GK.api('/teachers')` 返回老师列表，网络面板带 `/api` 前缀
- [ ] 带 token 时请求头含 `Authorization: Bearer`
- [ ] 429 的 `detail`（额度用完）能被上层正确展示
- [ ] `GK.sse` 能按 `start/delta/refs/done` 顺序触发回调
- [ ] 取消流后不再有 delta 回调（无泄漏）

## 8. 坑与注意事项

- 必须 POST（`/ask` 无 GET 语义），不能用 `EventSource`。
- 解析 SSE 时 `data:` 可能是多行，注意拼接；按空行分隔。
- nginx 已禁缓冲（`X-Accel-Buffering: no`），前端不要做整段缓存后一次性渲染（联动 A5 增量渲染）。

### 9.6 上报事项（不影响交付、需统筹知悉）

1. **④ SSE 静默关流** — `YOUR_SERVER_IP:3000/api/ask` 流式连接 status=200 但服务端在 `start` 事件之前就关闭响应。
   - 不是 A4 模块问题：A4 协议分发（`start/delta/refs/done/guard_block/error`）已由 `selftest-a4.js` 19/19 静态测试覆盖。
   - 怀疑后端 `api.py` 的 `ask_stream` 路径，LLM 调中转站 `ai.anyyds.cn` 在流式分支抛了未捕获异常 → close generator 而没发 `error` SSE 事件。
   - 建议：统筹排 B7（B4/B7 API 调用）时复现并修，建议加 `try/except` 在 `ask_stream` 外层，异常时 yield `{"type":"error","message":...}` 事件再 close。
   - 测试用 `scripts/probe-a4-sse.py`（已清理，可在 git 历史找回）。

2. **② 429 触发时同时夹杂 503** — 注册 free 账号狂问 21 次过程中，第 1-19 次偶现 503，第 20+ 次才稳出 429。
   - 503 来自 nginx（`Service Temporarily Unavailable` HTML 页面），非 A4 透出。
   - 502/503/504 走 nginx 默认 HTML 错误页，A4 把它当 detail 透给上层（业务方可识别为"网络层异常"）。
   - 建议：后续 nginx 配置 502/503/504 走 `application/json` 统一错误页（`/50x.html` → JSON 包装），便于前端结构化处理。**与本派单无关**。

3. **派单边界外发现** — 测试中发现 `auth.py` 的 401 也走 detail 透出，**目前与 02-数据契约 §3.2 一致**（`POST /login` 401+detail）。但**未在任务书要求中列出**，已通过自测覆盖，无新接口风险。
