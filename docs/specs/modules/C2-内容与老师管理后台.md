# C2 · 内容与老师管理后台（扩展业务域）

## 1. 目标

提供面向运营/内容方的管理后台：课件上传与删除、老师配置（新增/编辑/下线）、会员用户管理（手工开通/续费/回退），并可查看各老师知识库规模。

## 2. 现状

- 知识库已有 `POST /api/upload`、`GET /api/documents`、`DELETE /api/documents/{doc}`。
- 老师注册表在 `config.py::TEACHERS` 硬编码字典；无 admin 角色；无后台 UI。

## 3. 变更提案（需确认后写入 `02`）

### 3.1 角色扩展

`auth.py` 新增 `role=admin`（现仅 free/member）。admin 不占学员额度，可进入后台。首个 admin 由环境变量 `ADMIN_USERNAME` 初始化或命令行引导创建。

### 3.2 老师注册表持久化（重点变更）

将 `TEACHERS` 从「代码字典」改为「DB 表 + 运行时缓存」：

```text
表 teachers: teacher_id PK, teacher_name, teacher_subject,
             llm_model, temperature, top_n, threshold, enabled
```

`config.py` 启动时从 DB 加载，缺省回退到内置 T001/T002；新增 `enabled` 支持上/下线。

### 3.3 新接口（均需 admin Bearer）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/admin/teachers` | 老师列表（含 enabled） |
| POST | `/api/admin/teachers` | 新增老师 |
| PUT | `/api/admin/teachers/{id}` | 编辑参数 |
| DELETE | `/api/admin/teachers/{id}` | 下线（或改为 enabled=false） |
| GET | `/api/admin/users` | 用户列表（含 role/额度/到期） |
| POST | `/api/admin/users/{id}/set_role` | 手动开通/回退会员 |
| POST | `/api/admin/users/{id}/grant` | 手动充值额度/赠送天数 |

## 4. 功能点清单

1. 课件管理 UI：上传（带 `X-Upload-Secret`）、列表、删除，按老师维度。
2. 老师管理 UI：CRUD 表单，字段校验（teacher_id 唯一、阈值/top_n 合法）。
3. 会员管理 UI：搜索用户、看额度、手工开通/回退、赠送天数。
4. 前台联动：老师变更后 `GET /teachers`、`/info`、`store` 即时反映（启用/下线）。

## 5. 允许修改文件

- `backend/poc/config.py`（老师注册表运行时化，保持 `get_teacher/list_teachers` 签名兼容）
- `backend/poc/auth.py`（新增 admin 角色，不影响既有）
- 新建 `backend/poc/admin.py`、后台前端 `frontend/admin.html`（独立页，不经 `/api` 前缀的静态托管）
- `backend/poc/api.py` 新增 `/admin/*` 路由

## 6. 验收标准

- [ ] admin 登录后可增删改老师，前台老师列表即时同步
- [ ] enabled=false 的老师不出现在前台，但历史会话可读
- [ ] 课件上传/列表/删除在后台可用且触发缓存失效
- [ ] 手工开通/回退会员正确反映到额度和前台

## 7. 坑与注意事项

- 老师注册表运行时化是**高风险变更**：务必保持 `get_teacher()/list_teachers()` 返回结构不变，避免 B3/B4 全线崩。
- 上传鉴权沿用 `UPLOAD_SECRET` + nginx 限流，后台不要绕过限流被公网滥用。
- 后台前端建议独立 `admin.html` + `admin.js`，不要混入学员 `index.html`。
