# C1 · 会员付费闭环（扩展业务域）

## 1. 目标

打通「免费试用 → 付费升级 → 会员额度生效 → 到期续费」的完整付费链路。基于现有 `role=free/member` + 每日额度（free 20 / member 200）扩展，不破坏现有匿名/免费体验。

## 2. 现状

- `auth.py`：已有 `role` 字段、`set_role(user_id, role)`、`check_quota`/`consume`（按 role 计额度）。
- **缺失**：定价、订单、支付、开通/续费、到期管理。

## 3. 变更提案（需统筹确认后写入 `02-数据契约.md`）

### 3.1 新表 `orders`（`auth.db` 或独立 `pay.db`）

| 字段 | 类型 | 说明 |
|---|---|---|
| order_id | TEXT PK | 本地订单号（uuid） |
| user_id | TEXT | 归属用户 |
| plan | TEXT | `month`/`quarter`/`year` |
| amount | INTEGER | 单位分 |
| status | TEXT | `pending`/`paid`/`expired`/`refunded` |
| pay_channel | TEXT | 支付渠道标识 |
| txn_id | TEXT | 支付平台流水号（唯一） |
| created_at / paid_at | TEXT | 时间 |

### 3.2 用户表新增字段（`users` 增列）

`member_expire_at`（会员到期时间，free 为空）；会员到期回退 free。

### 3.3 新接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/plans` | 定价方案列表（含价格/权益） |
| POST | `/api/orders` | 建单（需 Bearer），返回支付参数/二维码 |
| GET | `/api/orders/{order_id}` | 查单状态（前端轮询） |
| POST | `/api/orders/notify` | 支付回调（验签、幂等、开通 member） |
| GET | `/api/me/membership` | 会员状态与到期信息 |

## 4. 功能点清单

1. 定价：月/季/年档位（价格由统筹确定，权益=额度 200/天 + 增值功能权益）。
2. 建单：生成订单，返回支付入口（二维码/跳转）；未登录 401。
3. 支付回调：验签（防伪造）→ 更新订单 → `set_role(user_id,'member')` + 写 `member_expire_at` → 幂等（重复通知不重复开通）。
4. 到期：每日检查/惰性检查 `member_expire_at`，过期自动回退 free（`auth.py` 读 role 时判定）。
5. 前端（A1 扩展）：会员购买入口、订单状态轮询、开通成功刷新额度。

## 5. 允许修改文件

- `backend/poc/auth.py`（新增字段/到期判定，不动既有签名）
- 新建 `backend/poc/payment.py`
- `backend/poc/api.py` 新增路由（经 B1 统筹确认）
- `frontend/js/a1-auth.js` 增会员购买区

## 6. 验收标准

- [ ] 建单 → 回调（模拟）→ 角色变 member → 额度升至 200/天
- [ ] 回调验签失败被拒；重复通知幂等
- [ ] 到期自动回退 free 且额度降回 20/天
- [ ] 匿名/免费体验不受影响

## 7. 坑与注意事项

- **支付渠道合规**：微信/支付宝个人商户受限；建议先做「充值码/后台手动开通」轻量方案跑通，再接第三方聚合支付（易支付/虎皮椒等），渠道凭据放 `.env`，不进代码库。
- 回调验签必须服务端完成，前端不可信。
- 到期判定与 `check_quota`/`consume` 解耦，避免每次请求都查库；可缓存。
- **幂等性**：同一充值码多次激活只开通一次会员，后续直接返回原结果。
- **数据库隔离**：支付数据放独立 `pay.db`，不影响 `auth.db`/`chat.db`。
- **阶段二预留**：`/orders/notify` 验签逻辑已预留（注释掉），阶段二接入第三方支付时取消注释并填入真实密钥。

### 8.4 关键设计决策

1. **充值码方案**：阶段一用充值码激活，管理员通过 CLI 生成码分发给学员，避免接第三方支付。
2. **惰性到期**：不在每次请求时检查到期，而在 `get_user()` 读取时检查并回退 free，性能友好。
3. **幂等保护**：充值码激活时若同一用户重复使用，直接返回原结果而不重复开通。
4. **数据库隔离**：支付数据独立存储，便于后续迁移或审计。
