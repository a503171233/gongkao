## 一、系统架构

### 1.1 技术栈与部署拓扑

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | FastAPI + Uvicorn (Python 3.11) | 端口 9000，容器 `gongkao-backend` |
| 前端 | 原生 HTML/JS + Nginx 1.27 | 端口 3000（对外），容器 `gongkao-frontend` |
| 数据 | SQLite（WAL） + 向量检索 | 挂载卷持久化 |
| AI | OpenAI 兼容协议（中转站） | 全局 .env 密钥 + 模型级独立密钥 |
| 部署 | Docker Compose（backend/frontend 双容器） | 服务器 YOUR_SERVER_IP |

**网络关键点**：后端 9000 端口**不映射到宿主机**，所有 API 请求经前端容器 Nginx 的 `/api/` 反代到 `backend:9000`。线上验证一律走 `http://YOUR_SERVER_IP:3000/api/...`。Nginx 读写超时已放宽至 600s（长文档 AI 处理防 504）。

### 1.2 后端核心模块（backend/poc/）

| 文件 | 职责 |
|---|---|
| `api.py` | 全部 HTTP 路由：公开接口、学员端、管理端（/admin/*） |
| `auth.py` | 登录/JWT/限流/角色（admin 账号启动时自动初始化） |
| `store.py` | 学员/会话/文档/消息等主数据（_GLOBAL 配置含全局 AI 密钥） |
| `models.py` | AI 模型注册表 AiModelStore（ai_models + ai_settings 表） |
| `llm.py` | LLM 调用层：`call_llm`（同步）/ 流式，支持模型级通道透传 |
| `admin.py` | 平台级 AI 业务：题库抽取、知识建树、节点描述、批量采集 |
| `qcategory.py` | 题库分类管理（注意 `row_factory = sqlite3.Row`） |

### 1.3 前端页面（frontend/）

`index.html`（官网）、`chat.html`（学员问答）、`dashboard.html`（学员面板）、`knowledge.html`（知识体系）、`admin.html`（管理后台，引用 `admin.js?v=YYYYMMDDx`）。

**版本号约定**：静态资源一律带 `?v=` 查询串，每次改动 JS 必须同步递增引用处的版本号，否则浏览器缓存旧文件，表现为"部署了但看不到新功能"。

## 二、AI 模型管理模块设计（2026-09-06 定稿）

### 2.1 数据表 `ai_models`

```sql
CREATE TABLE ai_models (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    model_id TEXT NOT NULL UNIQUE,   -- 模型标识，可含 / 与 [ ]（如 deepseek-ai/DeepSeek-V4-Pro）
    provider TEXT DEFAULT 'anyyds',
    base_url TEXT DEFAULT '',        -- 入库时自动归一化
    api_key TEXT DEFAULT '',         -- 模型级独立密钥（旧库幂等迁移：PRAGMA 检测缺列 → ALTER TABLE）
    enabled INTEGER NOT NULL DEFAULT 1,
    temperature REAL DEFAULT 0.3,
    max_tokens INTEGER DEFAULT 2000,
    is_default INTEGER NOT NULL DEFAULT 0,
    remark TEXT DEFAULT '',
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
```

另有一张 `ai_settings(key, value)`，存 `default_model`（平台级默认模型 id）。

### 2.2 关键设计决策

1. **Base URL 归一化（`_norm_base_url`）**
   OpenAI 客户端会在 base_url 后自动拼 `/chat/completions`。若从"获取模型列表"接口把 `…/v1/models` 原样入库，测速时会拼成 `…/v1/models/chat/completions` 导致 404/503。因此**入库（create/update）与读取（effective/test）双层归一化**：去尾部 `/models` 与斜杠；空值回退 `https://ai.anyyds.cn/v1`。

2. **密钥三级优先级**
   测速/调用时：`请求体显式 api_key` > `注册表保存的 api_key` > `全局 .env`。

3. **脱敏规则（`_mask_key`）**
   保留前 4 位与末 4 位，中间 `****`；短密钥保留前 2 末 2。
   - `list_models` / `GET /admin/ai-models/effective`：返回脱敏值；
   - `get_model` / `GET /admin/ai-models/{model_id}`：返回**明文**（仅管理端编辑回显与后端测试用）；
   - `update_model` 的 PATCH 语义：api_key 为**空串或含 `****` 视为不修改**（防止脱敏回显值被存回库里）。

4. **平台级 AI 通道（`effective_default`）**
   题库采集/抽取/知识建树等平台 AI 不再固定走全局 .env，而是经 `admin.py::_aim_eff()` → `effective_default()` 拿到 `{model_id, base_url, api_key, ...}`，经 `llm.py` 的 `_openai(base_url, api_key)` 直连所选默认模型的通道。默认模型被删/停用时自动回退全局 .env。

5. **模型 id 含斜杠的路由处理**
   中转站模型名常含 `/`（如 `deepseek-ai/DeepSeek-V4-Pro`）。前端 `encodeURIComponent` 产生的 `%2F` 会被 uvicorn 解码回 `/`，FastAPI 单段路径参数 `{model_id}` 匹配失败 404。因此 4 个动态路由统一使用 **`{model_id:path}`** 转换器（PATCH / DELETE / GET 详情 / 设默认）。
   **路由注册顺序红线**：静态路由 `builtin`、`effective`、`test`、`test-all` 必须注册在动态路由之前（FastAPI 按注册顺序匹配）。

6. **测速反假阳性（三种）**
   - 部分网关对 `/chat/completions` 返回 200 + HTML 页面（如 ps.air-outer.com）→ 检测 `<!doctype`/`<html` 前缀判失败；
   - 通道把错误提示当正文返回（`⚠️ 所有模型均不可用: HTTP 429`，多为限流/上游故障）→ 检测 `⚠` 前缀或"所有模型均不可用"判失败；
   - `choices=None` 等异常结构 → 解析须 `except (AttributeError, TypeError, IndexError)` 兜底 `str(resp)`。
   测速 `max_tokens=128`：思考型模型（agnes/glm-free/deepseek 等带 reasoning_content）的推理会消耗额度，16 会导致正文为空。

7. **错误信息友好化（`_aim_error_msg`，/test 与 /test-all 共用）**
   503 `No available channel` → "密钥分组下无此模型通道（可能已下线/密钥无权/通道临时禁用稍后恢复）"；400 未定价 → "站点管理员尚未定价"；图片/视频模型 → "不支持对话接口"；429 → "限流，稍后重试"；401/403 → 鉴权/上游拒绝。

8. **密钥分组（中转站 new-api 机制，务必理解）**
   `/models` 列表与对话通道均按 token 的分组返回：**不同密钥可见/可用的模型不同**。本项目全局 .env 密钥（default 组）与用户提供的密钥（通用API 组）模型列表互有差异。因此"获取模型"弹窗填写的密钥会**随一键登记保存到模型**（`window._aimLast.key` → `aimRegisterRemote`），测速按"表单/模型/全局"三级密钥解析。若测速报"无通道"而此前可用，多为网关通道临时禁用（自动恢复），非代码问题。

9. **批量测速（test-all）注意**
   必须用 `get_model()` 取**明文**密钥（`list_models()` 返回脱敏值，含 `****` 会被误判"未配置"）；并发限制 4（`threading.Semaphore`），密集测速可能触发网关 RPM 限流（429）或通道自动禁用。

### 2.3 API 端点一览（均需 admin Bearer Token）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/ai-models` | 列表（api_key 脱敏） |
| POST | `/admin/ai-models` | 新增（含 api_key，base_url 自动归一化） |
| GET | `/admin/ai-models/builtin` | 内置模型目录 |
| POST | `/admin/ai-models/list-remote` | 拉取远端模型列表（支持传 api_key） |
| PATCH | `/admin/ai-models/{model_id:path}` | 更新（api_key 留空/含****=不改） |
| DELETE | `/admin/ai-models/{model_id:path}` | 删除（默认模型联动清除设置） |
| POST | `/admin/ai-models/{model_id:path}/default` | 设为平台默认 |
| GET | `/admin/ai-models/effective` | 当前生效配置（脱敏） |
| GET | `/admin/ai-models/{model_id:path}` | 详情（**明文 api_key**，编辑回显用） |
| POST | `/admin/ai-models/test` | 单模型测速（密钥三级优先级） |
| POST | `/admin/ai-models/test-all` | 批量并发测速，按延迟排序 |

### 2.4 管理页交互（admin.js）

- 表格含 Base URL / API Key 列，独立 Key 显脱敏值、全局显徽标；
- 新增/编辑弹窗含 API Key 输入框（编辑留空 = 不修改，placeholder 有提示）；
- 弹窗内"测试连接"（`aimTestForm`）：以当前表单值即时测速；
- 行内测速按钮 loading/结果态（用 `document.getElementById`，因模型 id 含点号不能走 querySelector）；
- "一键测速"调 `test-all`；
- "获取模型"弹窗支持传 API Key，登记时自动归一化 base_url。

## 三、常见问题与解决方案

| 症状 | 根因 | 解法 |
|---|---|---|
| 拉取列表正常但测速 503"无通道" | 密钥分组：拉取与测速用的不是同一把密钥（分组不同→可用模型不同） | 拉取弹窗填密钥（会随登记保存）；或编辑模型配独立密钥 |
| 刚才测速 ok 现在报"无通道" | 网关通道临时禁用（自动恢复）或密钥 RPM 限流 | 稍后重试；避免密集连点一键测速 |
| 测速 ok 但回复是 ⚠️/网页 | 通道把错误文本/HTML 当正文返回 | 已检测判失败；核对 Base URL 是否 API 端点 |
| 测速 ok 但 reply 为空 | 思考型模型推理耗尽 max_tokens | 测速已用 max_tokens=128 |
| 测速全部失败/503 | base_url 入库带 `/models` 后缀 | 已双层归一化；历史数据可 PATCH `{base_url: 旧值}` 触发归一化 |
| 本地改了代码线上不生效 | deploy.py FILES 清单漏文件（如 llm.py） | 改动文件必须确认在 FILES 清单；容器内 `grep` 新标记验证 |
| 编辑/删除含 `/` 的模型 404 | `%2F` 被 uvicorn 解码，单段路由不匹配 | 路由用 `{model_id:path}` |
| 测速显示 ok 但回复是 HTML | 网关 200 返回网页，SDK 宽松解析 | 检测 `<!doctype`/`<html` 前缀判失败 |
| 页面部署后仍旧功能 | 浏览器缓存旧 JS | 递增 `admin.js?v=` 版本号 |
| 新静态页打开是首页 | frontend/Dockerfile COPY 漏文件，nginx try_files 兜底 index.html | 补 COPY 行并重建 frontend |
| 验证脚本连不上后端 9000 | 端口不映射宿主机 | 走 `http://YOUR_SERVER_IP:3000/api` |
| 长文档 AI 处理 504 | Nginx 代理超时 | 已放宽 600s |
| sqlite `dict(row)` 报错 | 缺 `row_factory = sqlite3.Row` | 连接工厂统一设置 |
| 管理端登录被拒（验证脚本） | admin 登录限流 | 多脚本连跑间隔约 5 分钟 |

## 四、部署流程

### 4.1 标准部署（scripts/deploy.py）

```powershell
# 本机 python 不在 PATH，用全路径
C:\Users\常一锦\AppData\Local\Programs\Python\Python312\python.exe scripts\deploy.py --backend --frontend
```

流程：SFTP 上传 FILES 清单 → 容器内 `py_compile` 预检 → `docker compose build` → `up -d` → 健康检查。

当前 FILES 覆盖（15 个文件）：
- 后端 `backend/poc/`：api.py、study.py、auth.py、store.py、metrics.py、admin.py、models.py、**llm.py**、qcategory.py
- 前端：chat.html、js/c4-study.js、js/a5-render.js、dashboard.html、admin.html、admin.js

> ⚠️ 曾因清单漏 llm.py 导致"本地已修线上不生效"，新增后端模块必须同步补入 FILES。

**检查清单（改代码后必过）**：
1. 改动的每个文件都在 `deploy.py` 的 FILES 清单里；
2. 改了 JS → 递增 `admin.html` 里 `admin.js?v=` 版本号（当前 `20260906f`）；
3. 新增静态页 → 加入 `frontend/Dockerfile` COPY 行；
4. 必须先 `build` 再 `up -d`（只 up 不带新代码）。

服务器 SSH/SFTP 凭据见 `scripts/deploy.py`（勿写入文档/记忆/代码库其他位置）。

### 4.2 线上验证要点

- 接口验证走 `http://YOUR_SERVER_IP:3000/api`（admin 账号 admin/admin123）；
- AI 模型关键回归：
  1. `GET /admin/ai-models`：base_url 无 `/models` 后缀；
  2. `POST /admin/ai-models/test` `{"model_id": "gpt-5.6-luna"}` → `ok=true`；
  3. `GET /admin/ai-models/{含斜杠id}` → 200；
  4. `POST /admin/ai-models/test-all` → 错误信息为友好文案。
- 全量回归：`python scripts/regression.py`（65 用例；连续重跑需间隔约 5 分钟避 admin 登录限流）。

### 4.3 scripts 目录规范（2026-09-06 清理后）

| 脚本 | 用途 | 用法 |
|---|---|---|
| `deploy.py` | **唯一部署入口**（SFTP 上传 + 预检 + build/up + 冒烟） | `python scripts/deploy.py --backend --frontend` |
| `regression.py` | 线上全量回归（65 用例，可复跑） | `python scripts/regression.py` |
| `run_remote.py` | 通用远程命令执行（规避 PowerShell 管道/引号问题） | `python scripts/run_remote.py "<命令>"` |
| `health_check.py` | 线上体检：容器/健康/日志/资源/版本标记/数据卷 | `python scripts/health_check.py` |
| `check_frontend.py` | 前端静态复核：静态资源死链 + api() 调用 vs 后端路由悬空比对 | `python scripts/check_frontend.py` |
| `diff_remote.py` | 本地与远端文件 MD5 一致性校验 | `python scripts/diff_remote.py` |
| `selftest-a4.js` | A4 传输层静态契约自检（无需后端） | `node scripts/selftest-a4.js` |
| `backup.sh` / `alert.sh` / `setup-https.sh` | 服务器侧运维（备份/告警/HTTPS 配置） | 服务器上执行 |

**临时脚本约定**（2026-09-06 曾一次性清理 29 个堆积的历史脚本，引以为戒）：
1. 一次性诊断/探测脚本命名加 `_` 前缀（如 `_diag_gw.py`），**当次会话用完即删**；
2. 专项验证跑通后，有长期价值的断言并入 `regression.py`，不另存 `verify_*.py`；
3. 部署一律走 `deploy.py`（改 FILES 清单），不再新建 `deploy_<编号>.py` 变体；
4. 已清理（仅存结论于文档/记忆）：`deploy_26/26r3/29/front_fix/nginx26/r3_fix/r3_front`、`diag_*`、`cat_nginx`、`pathprobe`、`probe_site_info`、`read_env`、`run_debug_ai`、`run_norm_test`、`smoke_26`、`verify_29/a1/ai_*/c1c2/c4/p1`、`check_remote`。
