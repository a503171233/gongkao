# 图形推理题图片化方案评估（批次9.2 评估稿）

> 日期：2026-09-24 ｜ 状态：**评估完成，待决策实施**
> 背景：批次9.1 对粉笔纯图题（图形推理等）做了入库拦截，本文评估把图形信息救回来的可行路径。

---

## 1. 背景

图形推理题的题目信息全在图形里，题干文字只是模板句。批次9.1 起对「去 `[图]` 占位后实质文字 <40 字」的题做入库拦截（约 30 道/6 卷），理由：纯文本平台无法表达图形，入库即废题。

用户提出评估：把图形信息完整保留入库的方案。

## 2. 现状盘点（关键利好）

| 环节 | 现状 | 位置 |
|---|---|---|
| 图片落盘 | `data/qimg/{teacher_id}/`，内容寻址幂等命名 | `admin.py` 文档解析已用 |
| 图片服务 | `GET /api/qimg/{tid}/{fname}` 公开只读 | `api.py:2919` |

**结论：展示链路零改动**，只需采集侧把图片落盘并生成合规标记。

### 2.2 粉笔图片实测（2026-09-24，行政执法卷）

- URL 形态：`https://fb.fbstatic.cn/api/tarzan/images/{15位hex}.png?width=700`（双 CDN 域名：`fb.fbstatic.cn` / `fb.fenbike.cn`，可互为备份）
- **无防盗链**：裸 urllib（无 Cookie、无 Referer）直接 200，PNG 头 `89504e47` 验证通过
- 体积：单张约 4KB，6 卷估计图题 ~60 道、每道 1 张题干大图（选项无图，`o_img=0`），总存储 <1MB，可忽略
- 图形推理题形态：题干 1 张合成大图（5 个图形拼图）+ 选项为 ①②③ 文字组合

## 3. 方案对比

| | 方案 A：采集时下载本地化（推荐） | 方案 B：直引粉笔 CDN URL | 方案 C：实时代理转发 |

| 做法 | 采集时下载图片 → 内容寻址落盘 `data/qimg/` → 题干嵌 `![图N](/api/qimg/…)` | 题干直接嵌粉笔 URL | 后端加代理端点实时转发粉笔 CDN |

| 结论 | **✅ 推荐** | ❌ 不推荐 | ❌ 不推荐 |

## 4. 方案 A 实施设计

### 4.1 改动点（全部在 `poc/fenbi.py`，约 60 行）

1. **`_download_imgs(html, teacher_id)`**：
   - 提取 HTML 内 `<img src>` → 逐张下载（复用现有节流，双 CDN 域名互备）→ `md5(data)[:12].png` 内容寻址落盘 `data/qimg/{teacher_id}/`（幂等：同名跳过）→ 返回 `{原src → 本地URL}` 映射
   - 单张下载失败：该图保留 `[图]` 占位文本降级，不阻断整题
2. **`to_item` 改造**：
   - 题干/材料 HTML 先过 `_download_imgs` 替换 `<img>` → `![图N](/api/qimg/{tid}/{fname})` 再 `_strip_html`（strip 时保留图片标记）
   - item 带 `images` URL 列表（`add_question` 白名单校验天然接受 `/api/qimg/` 前缀）
3. **纯图题守卫调整**：删除「<40 字拦截」——题干带图标记后即为完整可作答题；保留「题干全空 → None」
4. **选项区**：实测选项无图（`o_img=0`），暂不处理选项图（留扩展点）

### 4.2 降级与边界

- 图片下载失败/超时（单张 10s）→ `[图]` 占位，题目照常入库（与现状一致）
- 粉笔 CDN 未来加防盗链 → `_download_imgs` 带 Cookie/Referer 重试一层兜底
- 重复采集：内容寻址幂等，同图不重复落盘；题目查重照旧

### 4.3 测试与验收

- 单测：HTML→标记替换、落盘命名、下载失败降级、images 白名单
- 真网验收：重采 1 卷 → 图推题前端练习页可见图形 → 判分/解析正常
- 预估工作量：**0.5~1 人日**（实现 + 测试 + 重采验证）
