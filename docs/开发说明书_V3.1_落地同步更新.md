## 一、设计 vs 实际：关键差异对照

> V3.0 是规划文档（含 Next.js / Milvus / Redis / PostgreSQL / DeepSeek 等选型）。
> 实际落地为轻量架构（服务器仅 2C/3.6G），差异如下：

| 维度 | V3.0 设计蓝图 | V3.1 实际落地 | 说明 |
|---|---|---|---|
| 网站一（前端） | Next.js 14（SSR） | **纯静态 HTML/CSS/JS**（frontend/，nginx :3000） | 无构建、改文件即生效；模块化为 `js/a1~a5+c4` |
| 网站二（内核） | FastAPI + LangChain | **FastAPI（backend/poc/，:9000 内网）** | 零 LangChain，全自研轻量管线 |
| 向量库 | Milvus 2.4 | **Chroma（PersistentClient，本地持久化）** | 每老师一个 collection：`teacher_{teacher_id}` |
| 关系存储 | PostgreSQL 15 + Redis | **SQLite（标准库，WAL）**：auth.db / chat.db / pay.db / study.db / teachers.db | 落 `/data` 挂载卷，重建容器不丢 |
| 缓存 | Redis | **进程内 TTLCache**（检索 5min / 回答 10min） | 知识库变更按老师前缀失效 |
| Embedding | bge-m3（API/自部署） | **本地 fastembed `BAAI/bge-small-zh-v1.5`**（512 维 ONNX） | 中转站无 embedding 通道；需 `HF_ENDPOINT=hf-mirror.com` |
| 底座大模型 | DeepSeek-V3 等 | **中转站 `gpt-5.6-luna`**（ai.anyyds.cn/v1，OpenAI 兼容） | 中转站 21 模型实测仅此稳定（deepseek 等 503） |
| 用户鉴权 | JWT + Refresh | **HMAC 签名 token（PBKDF2 密码哈希，7 天有效）** | token 可吊销（/me/logout 持久化黑名单） |
| 站间鉴权 | AccessKey + HMAC 签名 | nginx `/api/` 反代 + 同源 CSRF 校验 + X-Upload-Secret | 单机双容器，无跨站调用 |
| 部署 | Docker Compose（多服务） | **Docker Compose 双容器**：gongkao-backend + gongkao-frontend | 腾讯云 YOUR_SERVER_IP:3000 |
| 异步任务 | Celery + Redis | 无（同步 + SSE 流式；视频转写受阻跳过） | 2C 服务器不引入重型队列 |
| 视频转写 | 全自动流水线 | **501 桩接口**（`/api/audio/transcriptions`，WHISPER_* 门控） | ⛔ 死胡同：中转站无 whisper、无 ffmpeg、跑不动本地 ASR |

## 三、M2.5 已交付功能（V3.0 之后的增量，均线上）

### 3.1 会话历史持久化（chat.py）
- 接口：`GET /api/sessions?user_id=`、`GET /api/sessions/{id}/messages`、`DELETE /api/sessions/{id}`
- 登录用户会话绑定 user_id，匿名绑定 `anonymous`；多轮上下文注入上限 10 轮。

### 3.2 双层缓存（cache.py）
- 检索缓存（TTL 5min，键 `retr|{teacher}|{query}|{top_n}`）+ 回答缓存（TTL 10min，键含 history 哈希）。
- 知识库变更（上传/删除/老师参数变更）自动失效；幻觉拦截结果绝不入缓存（先守卫后缓存）。

### 3.3 幻觉检测三道关卡（guard.py，B8）
| 关卡 | 规则 | 拦截 reason |
|---|---|---|
| ① 无资料拒答 | 无命中（低于 threshold）→ 不调 LLM 直接拒答 | reference |
| ② 引用一致性 | 答案与检索片段须有公共 4-gram（跳标点/数字/通用词） | reference |
| ③ 事实校验 | 答案中所有数字（**含中文数字**）必须出现在片段 | fact |
| ④ 超纲反查 | ≥10 字断言句 embedding 反查，相似度 < 0.28 拦截 | out_of_scope |

> selftest 模式（哈希向量无语义）下超纲反查跳过；0.28 为实测平衡值勿乱改。

### 3.4 用户账号 / 会员额度（auth.py）
- 注册/登录/me、PBKDF2-HMAC-SHA256（12 万迭代）、token HMAC 签名 7 天。
- 额度：free 20 次/天、member 200 次/天、**匿名不限量**（验收策略）。
- 角色：free / member / **admin**（C2 新增，不占额度）。

### 3.5 Gitee OAuth 第三方登录（gitee.py）
- 🦊 一键登录：`/api/auth/gitee/login`(307) → callback(code 换 token → 自动建号/绑定) → 302 回首页带 `?token=`。
- 未配置凭据时优雅降级（status enabled=false / login 503）。

### 3.6 监控指标（metrics.py）
- `GET /api/metrics`：uptime/请求计数/状态码/ask 统计/老师分布/最近事件 + **p95/slo**（C5 增）。
- `GET /api/metrics/prometheus`：Prometheus 文本（`gk_*`）。

## 四、C 系列扩展域（V3.0 之后的增量，均线上）

### C1 会员付费闭环
- 表独立 pay.db（data/ 卷内）。接口：`/plans`（三档定价）/ `POST /orders`（建单）/ `GET /orders/{id}` / `POST /orders/recharge-code/activate`（充值码激活）/ `GET /orders/user` / `GET /me/membership`。
- 阶段一 = 充值码轻量版（管理员后台/CLI 生成一次性码，防枚举）；第三方支付待接入（凭据进 .env）。

- 已修复坑：静态路由必须先于动态路由注册；orders 不用 (user_id, created_at) 唯一索引（同秒撞约束）。

### C2 内容与老师管理后台（/admin.html）
- 入口：`http://<host>:3000/admin.html`，admin / admin123（.env 注入 ADMIN_*，startup 自动建号）。
- **4 个 tab**：📊 统计 / 👨🏫 老师管理（CRUD+上下线）/ 👥 用户管理（搜索+角色/天数）/ 📚 文档管理（按老师筛选+删除）。

- 关键坑：新增环境变量须同步改 docker-compose.yml environment 段（compose 无 env_file）；create_teacher 须 setdefault 默认参数（防 500）。

### C3 运营数据看板（/dashboard.html）

### C4 学员增值功能（study.db）

### C5 更多拓展（本地代码/配置已交付）

## 五、LLM 重试降级（B7，代码已就绪）

- 实现位置：`backend/poc/llm.py`（answer.py 薄委托）。
- 重试：网络类/5xx/超时最多 `LLM_MAX_RETRIES`（默认 2）次，线性退避 0.5s×attempt（上限 2s）；4xx/鉴权/参数错误不重试直接抛错。
- 降级：主模型耗尽后按 `FALLBACK_MODELS`（config.py，逗号分隔）依次尝试，每个仅 1 次；默认空列表 = 不降级。
- 流式纪律：重试/降级仅发生在**未产出任何 delta 前**；产出后断流直接抛错转 SSE error 事件（防重复 delta）。
- ⚠️ 降级模型需**实测可用后写入** config（当前中转站仅 gpt-5.6-luna 稳定，未实测前保持空）。

## 七、部署与排障要点（V3.1 新增教训）

1. **改代码必须 `docker compose build <svc> && up -d <svc>`**（缓存模式），只 up -d 不生效；禁用 `--no-cache`（pip 全量重装卡 20+ 分钟）。
2. **CLI/脚本方式入库后必须重启 backend**（⚠️ P0，2026-09-04 实测）：chromadb 1.5.9 常驻 API 进程与外部 CLI 进程写入不同步，会报 500 `Error creating hnsw segment reader: Nothing found on disk`（磁盘数据完好，`docker compose restart backend` 即恢复；T001 经 API 进程入库所以无此问题）。
3. nginx 反代 Host 必须用 `$http_host`（含端口），`$host` 剥端口会导致 CSRF Origin 校验 403。
4. .env 新增变量必须同步 patch docker-compose.yml environment 段，再 `up -d --force-recreate`。
5. 上传接口走 nginx 3 次/分钟限流；批量入库走 SFTP + 容器内 CLI ingest 绕过。
6. 前端镜像需含 `js/` 子目录 + admin.html + dashboard.html（缺文件时 nginx try_files 兜底 → 三页面同页）。
7. SSH host key 变化（VPS 重装）后：`ssh-keygen -R <IP>` 再重连。
