# 后台模块拓展指南 与 本轮四项拓展规格

> 版本：v1.0（2026-09-06）｜ 适用：书山公考平台（FastAPI + 原生JS + SQLite + Docker）
> 本文前半部分是**后台各模块拓展的通用开发说明**（长期有效），后半部分是本轮四项拓展的实施规格（开放 API 上传 / 看板 UI / 看板功能）。

---

## 第一部分 · 后台模块拓展通用开发说明

### 1. 三段式模块架构

每个后台功能模块都由三层组成，拓展时**先改数据层，再补业务层，最后挂路由层**，前端独立成模块函数：

| 层 | 文件 | 职责 | 拓展方式 |
|---|---|---|---|
| 数据层 | `backend/poc/store.py`（学员/会话/文档）、`study.py`（题库/练习/反馈）、`docreg.py`（文档注册表）、`qcategory.py`（题库分类）、`models.py`（AI模型） | SQLite CRUD，**必须** `row_factory = sqlite3.Row` | 新表在 `_init_schema` 建表；改表用 PRAGMA 检测缺列幂等 ALTER |
| 业务层 | `admin.py`（平台AI/备份/用户）、`metrics.py`（统计聚合） | 跨 store 的组合逻辑 | 纯函数，接收 db_path / store 实例 |
| 路由层 | `api.py` | `/admin/*`（需 admin Bearer 或 X-Admin-Secret）、公开路由 | Pydantic Req 模型 + `Header(default="")` 鉴权 |
| 前端 | `admin.js` 的 `TABS` 数组 + `render<Module>` 函数 | 单页后台 | 新模块 = 加 TABS 项 + 渲染函数 + 事件绑定 |

### 2. 现有模块清单与拓展点

| 模块 | 数据层 | 已有能力 | 推荐拓展方向 |
|---|---|---|---|
| 仪表盘 dashboard | metrics.py | 总览/额度/营收/老师热度 | 趋势对比、告警阈值 |
| 老师管理 teachers | store.py | CRUD/启停 | 头像上传、科目扩展 |
| AI模型 aimodels | models.py | 注册表/测速/默认模型 | 用量按模型统计、成本核算 |
| 用户管理 users | auth.py/admin.py | 列表/搜索/禁用/统计 | 批量导入、角色细分 |
| 文档管理 documents | store.py+docreg.py | 上传/预览/分类/标签/启停 | **开放 API 上传（本轮）**、重复检测 |
| 题库管理 questions | study.py+qcategory.py | CRUD/分类/批量/AI采集 | 导入导出、组卷 |
| 知识体系 knowledge | admin.py 建树 | 树/统计/节点描述 | 前台联动、导出 |
| 充值码 recharge | payment_store | 生成/核销 | 批量导出、订单报表 |
| 答案反馈 feedback | study.py | 统计/处理 | 看板可视化（本轮） |
| 数据备份 backups | admin.py | tar.gz 归档/恢复 | 定时备份、异地同步 |

### 3. 新增后台模块 SOP（八步）

1. 数据层：`_init_schema` 建表（含 `created_at/updated_at`），连接统一 `row_factory`；
2. 业务层：组合逻辑写 `admin.py` 或独立 `<domain>.py`，不直接碰 HTTP；
3. 路由层：`api.py` 定义 Pydantic Req + 端点，统一 `_admin_user()` 鉴权；
4. 路由红线：**静态子路径必须注册在动态 `{param}` 路由之前**；含 `/` 的业务 id 用 `{id:path}` 转换器；
5. 前端：`admin.js` 的 `TABS` 加项，新增 `render<Module>()` 与事件绑定；改 JS 必须递增 `admin.html` 的 `?v=`；
6. 部署：确认新文件已加入 `scripts/deploy.py` 的 FILES 清单（**漏文件=线上不生效**）；
7. 验证：断言式脚本验证（PASS/FAIL 计数），长期断言并入 `scripts/regression.py`；
8. 文档：更新 `docs/开发说明书.md` 对应章节 + 项目记忆 Lessons。

### 4. 对外开放模块的额外要求（Open API 规范）

内部 `/admin/*` 用 Bearer/Secret；**对外模块走版本化开放路径 `/api/v1/*`**，要求：

- **密钥鉴权**：`X-API-Key` 头 + `.env` 密钥（`hmac.compare_digest` 防时序攻击），未配置密钥时端点返回 503（明确"未启用"而非裸奔）；
- **限流**：内存滑动窗口 per-IP（如 10 次/分钟），超限 429 + `Retry-After`；
- **统一响应信封**：`{"code": 0, "message": "ok", "data": {...}}`，错误 `code != 0` + 可读 message；
- **CORS**：走全局 CORSMiddleware（已配置），第三方网页可直调；
- **输入加固**：文件名清洗（防穿越）、扩展名白名单、应用层大小上限、参数白名单校验；
- **可探测**：提供 `GET /api/v1/<module>/health` 让对接方先探测能力再集成。

## 第二部分 · 规格一：文档管理开放 API 上传

### 5. 需求与设计

**需求**：非登录用户（第三方脚本/外部系统）按固定格式通过 API 上传文档入库，不需要平台账号。

**端点设计**：

| 项 | 值 |
|---|---|
| `POST /api/v1/documents/upload` | 上传文档（multipart/form-data） |
| `GET /api/v1/documents/health` | 能力探测（公开）：是否启用/支持格式/大小上限 |

**请求格式**（multipart/form-data）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `file` | ✅ | 文件本体；白名单 `.md/.txt/.docx/.pptx/.pdf/.xlsx`；≤50MB；文件名清洗防穿越 |
| `teacher_id` | ✅ | 目标老师（须已启用，否则 404） |
| `category` | ❌ | 文档分类，默认 `API上传`；docreg 登记 |
| `tags` | ❌ | 逗号分隔标签（仅新登记文档生效；重传幂等保留人工标签） |

**鉴权**：`X-API-Key: <OPENAPI_KEY>`（`.env` 新增，32 位随机；与既有 `UPLOAD_SECRET` 独立，互不影响）。

**响应信封**：
```json
{"code": 0, "message": "ok", "data": {
  "doc_name": "讲义.md", "teacher_id": "T001",
  "chunks": 12, "stored": 12, "total": 345, "category": "API上传"}}
```

**错误码**：401 密钥缺失/错误；404 teacher 不存在或停用；400 格式/参数；413 超限；429 限流（Retry-After: 60）；503 服务端未配置 OPENAPI_KEY。

**安全决策**：新端点**强制**密钥（当前线上 `UPLOAD_SECRET` 未配置，既有 `/upload` 实际无保护——本规格不改动它以免破坏内部链路，但在运维上要求尽快为 `.env` 补 `OPENAPI_KEY` 并评估给 `/upload` 加密钥）。

**限流**：per-IP 滑动窗口 10 次/60s（内存实现，重启清零可接受）。

### 6. 复用与实现要点

- 完整复用 `/upload` 的加固逻辑（清洗→白名单→大小→ingest→upsert→docreg），抽取公共函数 `_ingest_upload(file, teacher_id, category)` 避免复制粘贴；
- `docreg.register(..., category=...)` 已支持分类参数；
- 限流器实现为模块级 `_RateWindow`（`collections.deque` + `threading.Lock`）；
- 健康端点公开返回 `{enabled, formats, max_mb, rate_limit}`。

## 第三部分 · 规格二：运营看板 UI 升级（书卷化）

### 7. 现状与目标

**现状**：`dashboard.html` 为独立蓝色主题（#4a6cf7 系），与全站"书卷暖纸色"（index/chat/admin/knowledge 均 `css/app.css`）风格割裂。

**目标**：看板全面切换书卷设计语言，视觉与前台/后台一致：

| 设计令牌 | 取值（app.css 已定义，直接引用） |
|---|---|
| 背景 | `--paper #f6f1e7` + 径向暖光纹理 |
| 卡片/面板 | `--card #fffaf0` + `--line` 边线 + `--shadow-1/2` |
| 主色 | `--wood #8b5e3c`（替换全部 #4a6cf7） |
| 点缀 | `--gold #c9a05a`、`--gold-soft` |
| 正/负向 | `--good #7a9e6d` / `--bad #b45a4a`（替换绿#16a34a/红#e5484d） |
| 导航 | `glass-nav` 毛玻璃 + `brand-mark` 书标 + 统一 nav-links |
| 动效 | `--spring` 弹簧曲线，卡片 hover 上浮 |
| 图表 | SVG 柱状 fill 改 `var(--wood)`，警示柱 `var(--bad)` |

**做法**：`<link rel="stylesheet" href="/css/app.css">` + 页内少量补充样式；不引入任何前端依赖，保持单文件内联 JS。

### 8. 验收标准（UI）

1. 看板导航/卡片/表格/徽标/图表全部呈现书卷暖色系，无蓝色残留；
2. 与 index.html 并排浏览无明显风格断裂；
3. 响应式（≤900px 单列）与既有功能不回归（全部既有面板正常渲染）；
4. 服务端 curl 验证 HTML 引用 `/css/app.css` 成功（200）。

## 第四部分 · 规格三：运营看板功能拓展

### 9. 新增功能（全部复用既有后端端点，零新增后端）

| # | 功能 | 数据源 | 说明 |
|---|---|---|---|
| F1 | 反馈统计面板 | `GET /admin/stats/feedback` | 好评率/总数/待处理卡片 + 最近反馈列表（老师/评分/摘要/状态） |
| F2 | 题库概览面板 | `GET /admin/questions/stats` | 题目总数 + 题型分布条形图 + 难度分布徽标 |
| F3 | 自动刷新 | 前端 | 30s/60s/关闭 三档；显示最后刷新时间；刷新失败自动暂停 |
| F4 | 凭据记忆 | localStorage | "记住密钥"勾选；刷新页面自动加载（密钥仅存本地） |
| F5 | JSON 快照导出 | 前端 | 在已有 CSV 导出旁增加"导出 JSON"（当前全部面板数据） |
| F6 | 键盘快捷键 | 前端 | `R` 手动刷新（输入框聚焦时除外） |

### 10. 交互与降级

- F1/F2 面板失败时**优雅降级**（面板内提示错误，不拖垮其他面板）——与既有 `/metrics` 降级策略一致；
- 未填密钥时仅健康面板可见（现状保留），其余面板提示先填密钥；
- 自动刷新与手动刷新共用 `loadAll()`，防重入（loading 期间跳过）。

### 11. 已知限制（明确不做）

- 不做按老师筛选联动全面板（feedback/questions 支持参数但 overview/quota 不支持，联动会误导）；
- 不做深色模式（书卷主题无深色令牌）；
- 密钥记忆依赖 localStorage，换浏览器/清缓存需重填。

## 第六部分 · 实施结果（2026-09-06 已上线）

- **开放 API**：`POST /api/v1/documents/upload` + `GET /api/v1/documents/health` 已上线，分两轮共 33 项断言全过（401/404/400/413/429/503 分支、成功上传、限流触发）。线上密钥已配置于服务器**根目录** `.env` 的 `OPENAPI_KEY`（`gk_open_` 前缀 32 hex），compose 已加透传行；
- **路径修正记录**：初版后端路由误带 `/api/v1` 前缀，经 nginx `/api/` 反代剥首段后外部 URL 变成 `/api/api/v1/*`（双前缀）。已修正为**后端路由 `/v1/documents/*`，对外 `/api/v1/documents/*`**，旧双前缀路径已消亡（复测 404），修正后 12 项断言全过、回归 65/65 无副作用；
- **上传链路重构**：`/upload` 与 v1 共用 `_validate_upload`（清洗/白名单/大小）+ `_save_and_ingest`（写盘/入库/docreg 登记），行为等价（回归 65/65 验证）；
- **看板书卷化**：dashboard.html 引入 `/css/app.css`，玻璃导航 + 暖纸卡片 + 木色图表，无蓝色残留；页面内覆盖 `.hint`（app.css 大空态样式冲突）；浏览器实测桌面 + 375px 移动端渲染正常；
- **看板功能**：F1 反馈面板（好评率 73.7% 实测渲染）、F2 题库面板（119 题/题型/难度）、F3 自动刷新、F4 凭据记忆、F5 JSON 导出、F6 R 快捷键全部上线；`API.get` 双头发送 `X-Admin-Secret` + `Authorization: Bearer`（兼容仅 Bearer 的 feedback/questions 端点）；
- **部署清单**：FILES 新增 `config.py`、`docker-compose.yml`（历史遗漏补齐）；
- **测试残留清理**：rl*.md / v1测试*.md 已通过 `/admin/documents/{name}` DELETE（注册表联动）清空。

**开放 API 调用示例**（第三方视角）：
```bash
# 1. 探测能力（公开）
curl http://YOUR_SERVER_IP:3000/api/v1/documents/health
# 2. 上传文档（注：nginx /api/ 反代会剥掉首段 /api，后端实际路由为 /v1/documents/*）
curl -H "X-API-Key: gk_open_xxx" \
     -F file=@讲义.md -F teacher_id=T001 -F category=API上传 -F tags=申论,讲义 \
     http://YOUR_SERVER_IP:3000/api/v1/documents/upload
```

**已知限制**：
- **外部访问必须带 `/api` 前缀**（nginx 仅反代 `location /api/` 并剥首段）：后端路由 `/v1/*` → 外部 `/api/v1/*`；后端 `/admin/*`、`/login` → 外部 `/api/admin/*`、`/api/login`。裸 `/admin/...` 落到静态 location，DELETE/POST 会被 nginx 405/404 拒绝；
- 限流为单实例内存窗口（重启清零，多副本部署需换 Redis）；
- 测试用例中 T999 为历史测试创建的真实老师，勿再用作"不存在"样本；
- `DELETE /documents/{name}`（公开端点）只删向量块不清注册表，清理须走管理端 `/admin/documents/{name}`。
