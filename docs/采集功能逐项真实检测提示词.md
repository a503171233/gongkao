## 1. 检测纪律（硬性约束）

1. **先备份、后恢复**：测试开始前保存
   `GET /api/admin/autocollect/config` 与 `GET /api/admin/autocollect/llm/channels` 的完整 JSON；
   所有配置类测试结束后 PUT/重建回原值，并 GET 复核恢复成功。
2. **LLM 成本控制**：真实运行采集（/run）全程最多 1 次；执行前把
   `max_per_cycle` 临时调小（如 5）且 `llm_budget_chars` 设小值，跑完立即恢复。
3. **数据零污染**：冒烟文档用 `_检测_` 前缀命名，测完 `DELETE /api/admin/documents/{doc_name}` 真删；
   套卷 reset 只允许对**单个测试 URL** 操作，禁止"重置全部"。
4. **每项结论三态**：PASS / FAIL / BLOCKED（无法真实执行时注明原因），
   FAIL 必须附根因线索（响应体、日志尾部、容器状态）。
5. 破坏性开关（停用守护、清空通道）验证后立即恢复，恢复动作本身也是检测项。

## 4. 报告格式（输出给我）
- 逐条矩阵表：`编号 | 模块 | 检测项 | 方法(API/浏览器/容器内) | 预期 | 实际 | 证据摘录 | PASS/FAIL/BLOCKED`
- 证据摘录必须含真实返回值（状态码+关键字段/截图文件名），不接受"符合预期"四字了事。
- 末尾：失败项根因分析（日志尾部/代码位置）、成本统计（/run 次数、LLM 调用量）、
  恢复确认清单、总体结论（可发布/需修复清单）。
