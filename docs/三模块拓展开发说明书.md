**缺失**：课程/公司分类、排序字段；无批量排序端点；公开 /teachers 无分类信息。

### 2.2 题库 AI 采集（backend/poc/admin.py 527-906 行 + study.py + ingest.py）
**已有**：
- 链路：`/admin/questions/parse-file`（extract_text 解析）→ 前端确认 → `/admin/questions/extract`（LLM 提取，BATCH=2500、12 批上限、3 次重试 + 拆半递归 + 0.75 漏题回采）→ `/admin/questions/import`（add_questions_batch 入库，按题干全文判重）
- 容错解析：_parse_llm_json_array 三策略 + _salvage_json_objects 截断抢救
- _normalize_questions：qtype 中文映射/options 对象转数组/difficulty 中文映射

**根因（三个真 Bug）**：
1. **图片全丢**：`ingest.extract_text` 中 docx 只取 `par.text`（w:drawing 完全忽略）、pptx 只取 text_frame、pdf 只 `get_text("text")`；question_bank 表无 images 列。图形推理/资料分析图表题采集后只剩文字描述，图片内容丢失。
2. **去重键误并**：`absorb()` 去重键 = `question[:80] + 选项[:60]`。资料分析子题的 question = 共享材料 + 子题问题 → 前 80 字全是材料 → **choice 子题靠选项区分侥幸不并，judge/essay 子题（无选项）前 80 字相同 → 多题被误并为 1 题**，表现为"只采集到第一题"。
3. **prompt 无材料题规则**：资料分析"一段材料 + 5 子题"场景，LLM 可能只把材料挂第一题、其余子题丢材料或漏采。`_count_question_floor` 按"答案："行计数可触发回采，但正常路径无专项约束。

### 2.3 知识体系（backend/poc/knowledge.py + api.py #20/#21/#24 段）
**已有**：knowledge_nodes 表（node_id/teacher_id/parent_id/name/category/description/sort_order/tree_type），树 CRUD/批量移动删除/AI 思维导图/三格式导出；开放 API v1 基础设施（_RateWindow/_client_ip/_v1_err/X-API-Key 校验模式）。
**缺失**：对外开放上传入口；无 Markdown → 树的导入解析器（只有导出 to_markdown）。

### 3.3 请求/响应格式

**排序**：`PUT /api/admin/teachers/sort`
```json
{"items": [{"teacher_id": "T001", "sort_order": 1}, {"teacher_id": "T002", "sort_order": 2}]}
→ {"updated": 2}
```

**知识上传**：`POST /api/v1/knowledge/upload`（multipart/form-data）
| 字段 | 必填 | 说明 |
|---|---|---|
| file | ✔ | .md/.txt，≤5MB，按标题层级建树 |
| teacher_id | ✔ | 已存在且启用的老师 |
| parent_id | ✘ | 挂载父节点（默认根级） |
| category | ✘ | 节点分类标签（≤30 字） |

```json
→ {"code": 0, "message": "ok", "data": {"created": 12, "skipped": 2,
    "root_node_id": "KNxxxx", "skipped_names": ["主旨概括（已存在）"]}}
```

**Markdown 建树格式约定**（对外发布）：
```markdown
# 言语理解与表达        ← 顶级节点
## 主旨概括             ← 二级节点
核心考点：……            ← 节点说明（≤500 字）
## 意图判断
……
# 判断推理
## 图形推理
……
```
规则：`#` 层级 = 树层级（最深 `######` 六级）；标题下正文 = description；无任何标题时整文档作单节点（名=文件名）。

## 四、实现方案

### 4.1 老师管理（改动：config.py / admin.py / api.py / admin.js）
1. **config.py**：`_init_teachers_schema` 加三个 ALTER（幂等）；`reload_teachers` 缓存透传三字段（`"course_category" in r.keys()` 防御式读取，旧库启动顺序兼容）。
2. **admin.py**：`_validate_teacher_payload` 加 course_category/company/sort_order 校验（strip、≤30/≤30/≥0 整数）；create INSERT 加列；update SET 加列。
3. **api.py**：`PUT /admin/teachers/sort`（校验 items 非空、teacher 存在、sort_order 0~9999；批量 UPDATE 后 reload + 缓存失效）；注册顺序置于动态路由前。
4. **admin.js**：表单加"课程分类/公司"输入（datalist 建议项：言语理解/判断推理/数量关系/资料分析/常识判断/申论/面试；机构建议项自定义）；列表加两列徽标；工具栏加"排序模式"（↑↓ + 保存调 sort 端点）；分类下拉本地过滤。

### 4.2 题库采集修复（改动：ingest.py / admin.py / study.py / api.py / admin.js）
1. **ingest.py 新增 `extract_collect(path, img_dir) -> dict`**（采集专用，不动 extract_text 签名——文档入库链路零影响）：
   - 返回 `{text, images: [{marker: "图1", url: "/api/qimg/T001/abc.png"}], n_img}`
   - docx：遍历 `d.paragraphs`，段内 `par._element.findall('.//{drawing}')` → `a:blip` 的 `r:embed` rId → `d.part.related_parts[rId].blob`，段落文本后追加 `![图N](url)`
   - pdf：`page.get_text("dict")` 按 block 顺序重建，type=1 的 image block 取 `block["image"]` bytes
   - pptx：shape 无 text_frame 但 `shape_type == PICTURE` → `shape.image.blob`
   - 图片字节 sha1 前 12 位为文件名（内容寻址，同图去重），magic bytes 判扩展名，落盘 img_dir；**单图失败 try/except 跳过并在文本中保留 `[图片提取失败]` 标记**
2. **api.py 新增 `GET /qimg/{teacher_id}/{fname}`**：FileResponse + fname 正则白名单 + 路径拼接后 resolve 校验仍在 qimg 目录内（双防穿越）；Cache-Control 长缓存（内容寻址不可变）。
3. **admin.py `parse_collect_file`**：改用 extract_collect，图片落盘到 `cfg.data_dir/qimg/{teacher_id}`（需 teacher_id 参数，端点透传）；返回 {doc_name, chars, text, n_img}。
4. **`extract_questions_ai` prompt 增强**（两段新规则）：
   - 图片："题干中的 `![图N](...)` 图片标记必须**原样完整**复制进 question 字段（保持 markdown 格式与 URL 不变），禁止丢弃、禁止改写 URL"
   - 资料分析："资料分析/一拖多题组（一段材料 + 多道子题）：每道子题独立输出一道题，question = **完整共享材料 + 该子题题干**（保证单独可读）；禁止只输出第一道、禁止丢弃材料、禁止用'材料同上'省略"
5. **去重键修复**：`key = q["question"][:80] + "|" + "".join(options)[:60] + "|" + q["question"][-60:]`（题干末 60 字 = 子题问题部分，区分度所在）。
6. **入库校验（study.py add_questions_batch）**：
   - choice 且 len(options) < 2 → skipped_invalid +1
   - choice 且 answer 无法匹配选项字母（A-D 归一化）→ skipped_invalid +1
   - question 中提取 `/api/qimg/` URL → images 列（JSON）；孤立 `[图N]` 文本标记（无对应 URL）清理
   - 返回 {added, skipped, skipped_invalid}
7. **admin.js**：题干渲染函数 `qText(q)`（esc 后把 `![...](白名单URL)` 替换 `<img loading="lazy">`，URL 仅允许 `^/api/qimg/`，防 XSS）；采集结果弹窗显示"含图 N 题"。

### 4.3 知识体系开放 API（改动：api.py + 文档）
1. **api.py**：
   - `GET /v1/knowledge/health`：{enabled, formats: [".md", ".txt"], max_mb: 5, limits: "300 节点/次，层级≤6"}
   - `POST /v1/knowledge/upload`：鉴权（hmac）→ 限流（独立 `_RateWindow(6, 60)`）→ teacher 校验 → 文件校验（类型/大小/UTF-8）→ `_md_to_tree()` 解析 → 节点上限/深度校验 → 逐节点 `ks.create_node`（同名跳过）→ 信封返回
2. **`_md_to_tree(text, doc_name)` 解析器**（api.py 内私有函数）：
   - 逐行扫描 `^(#{1,6})\s+(.+)$`；维护层级栈（当前各深度的父 node_id）
   - 标题 → 新节点（name=标题，description=该标题下至下一标题的正文合并，截 500 字）
   - 无标题文档 → 单节点（name=文件名去扩展名，description=全文截 500）
   - 层级跳跃（如 # 后直接 ###）→ 按出现顺序降级为"上一节点 +1 级"（树的性质：不许跳级孤儿）
3. **限流与安全**：X-API-Key 同 documents（OPENAPI_KEY 同一把密钥，简化对接方）；限流 6 次/分钟/IP（建树比上传文档轻，但防滥用）；错误分支 401/404/400/413/429/503 齐全。

### 已知限制
- LLM 提取对图片标记的保留为 prompt 约束 + 入库清洗双保险，极端情况下模型仍可能挪动标记位置（人工核对入口在采集确认界面）。
- docx 表格内嵌图片（w:tbl 内 drawing）暂不在提取范围（题目正文段落级已覆盖）；需要时可在 _docx_collect 扩展遍历 table.rows。
- 资料分析超长材料（>2500 字）跨批时依赖 prompt 规则 + 漏题回采保证子题完整，实测样卷（约 900 字材料+5 子题）5/5 全收。
- /v1/knowledge/upload 的 503 分支（未配 OPENAPI_KEY）因生产已配 key 无法在线触发，仅代码审查覆盖。
- 题库 CSV 导出中题干图片标记原样保留（可读文本），不做 URL 展开。
